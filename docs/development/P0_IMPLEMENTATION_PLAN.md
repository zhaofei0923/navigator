# V1.0 P0 逐步开发与验收计划

> 基线：V1.0-BASELINE
> 更新日期：2026-07-31
> 当前阶段：D0 数据标准冻结
> 强制门禁：D4 正式评审通过后，方可启动 V0.1 用户侧产品开发

## 1. 当前结论

仓库以已经审核的文档和技术附件为基线，现已建立 D0—D4 数据就绪工具与自动测试；
应用代码、数据库迁移和部署环境尚未建立。D0 台账显示：

- D0-01“冻结核心实体和字段集”进行中；
- D0-02、D0-03、D0-04未开始；
- 9个责任角色均待实名签署；
- 10个D0硬门均未验收；
- D1—D4任务均未开始，D4量化得分为0。

机器可验证部分已经建立并执行。当前新增发现：

- 25条核心实体关系的必填结构检查通过；
- 92个冻结字段的唯一标识和基础元数据检查通过；
- 251条枚举的对象内代码唯一性检查通过，迁移语义仍待业务复核；
- 批次、国家、来源及原始资料示例的引用关系检查通过；
- 6条字段映射模板均引用冻结字段清单中不存在的目标，因此D0-03模板试填不通过；
- 印尼 ESDM HEESI 2024 和越南 EVN Annual Report 2024-2025 已完成官方来源、
  发布日期、采集时间、SHA-256、PDF安全属性和封面核验；
- 上述两份原件仍缺获批许可快照和专业复核，且模板行仍为示例；沙特样例尚未绑定
  具体原件，因此3条样例均不能作为正式金标准。
- D0正式评审模板已经建立，可一次性收集9个责任角色、6条字段映射、3条样本、
  3份候选规范、10项硬门和最终D0结论，并在提交前校验基线哈希与字段完整性。
- D1来源准入候选包已经建立：在18个冻结起始来源之外，已登记41个五国官方研究
  候选，国家候选数量达到印尼20、越南8、沙特8、南非8、巴西8。59个候选全部保持
  `under_review`，active数量仍为0；条款、许可、robots、访问和AI边界尚未批准，
  五国40个核心域优先/替代源组合尚待正式绑定。
- D2不可变原始采集候选包已经建立：6个冻结批次已生成任务合同；当前没有获准运行、
  L0原始对象或已关闭批次，D1来源未active前不得执行。运行水位、重试、停止信号、
  原件哈希、秘密日志、异常和跨批次证据均已纳入机器门禁。
- D3可重放处理候选包已经建立：解析、标准化和实体解析三段流水线均要求固定配置、
  代码/规则版本、参数与输入输出清单哈希。候选记录逐条绑定不可变L0对象，原文、
  译文、原值、单位/币种/时间转换、实体决策、冲突和可撤销合并均纳入机器门禁；
  D2未关闭或任何记录被标记可发布/可进入AI索引时必须失败。
- D4质量与正式验收候选包已经建立：五国最低样本、七维100分评分、双人分层抽样、
  追溯/许可/准确率/重复率/P0硬门、种子导入/重建/回滚、来源撤权、RAG权限、
  九项移交和五类实名批准均可机器复算；当前无真实D3发布记录、演练证据或D4签署，
  因此D4仍未通过，V0.1继续阻断。

字段映射差异如下，任何修正都必须同步更新正式附件并取得批准：

| 映射编号 | 当前目标 | 处理边界 |
|---|---|---|
| MAP-COUNTRY-NAME | `country.name_zh` | 冻结字段不存在；应由数据负责人决定进入本地化名称实体还是补充字段 |
| MAP-ISO3 | `country.iso3` | 权威冻结字段为`country.iso_code`，仍需正式更正记录 |
| MAP-POLICY-DATE | `policy.published_at` | 冻结字段仅有`effective_date`；发布日期与生效日语义不同，禁止直接替换 |
| MAP-PROJECT-CAP | `project.capacity_mw` | 冻结字段不存在；需确认容量所属实体、原值和标准单位字段 |
| MAP-AMOUNT | `tender.budget_original` | 冻结字段不存在；需确认原币、原值、汇率及换算字段 |
| MAP-ENTITY | `partner.legal_name` | 冻结字段不存在；需确认伙伴与法律主体主数据边界 |

因此，当前不能诚实地开始 V0.1 用户侧功能，也不能把文档确认等同于 D0、D4或P0
验收。开发将严格按照下列阶段门推进。

## 2. 阶段一：D0 数据标准冻结

### 2.1 工具与合同基线

1. 建立只读工作簿解析器，提取实体、字段、枚举、采集规则和质量规则；
2. 对所有唯一编号、依赖、国家范围和任务状态执行结构校验；
3. 生成带源工作簿 SHA-256 的 JSON 合同快照；
4. 建立证据清单格式，校验证据路径、哈希和验收项关联；
5. 建立 D0 报告与硬门命令，未签署或缺证据时必须非零退出。

### 2.2 业务执行

1. 项目批准人补齐9个角色的姓名、替补、联系方式和签署日期；
2. 数据负责人完成核心实体、字段、主键和权威关系复核；
3. 产品/数据负责人冻结枚举、单位、时区、精度和多语言规则；
4. 数据质量负责人用至少一套跨实体样本试填来源、原始资料、映射、审核和D4模板；
5. 研究与审校负责人提交金标准样本和术语表；
6. 逐项提交 D0-AC-001 至 D0-AC-010 证据并由指定复核人签署。

### 2.3 D0退出标准

- D0-01至D0-04全部完成；
- 9个角色完成实名与替补签署；
- 10个D0硬门全部通过；
- 阻塞项为0，遗留问题均有责任人和目标日期；
- 项目批准人签署D0通过结论。

## 3. 阶段二：D1 来源准入

1. 对跨国来源、印尼来源及四个比较国来源逐一建档；
2. 保存当日条款、许可、访问方式、再分发和AI使用边界快照；
3. 为核心数据域登记优先来源和替代来源；
4. 禁止绕过登录、验证码、robots、速率限制或付费边界；
5. 只有准入状态为 `active` 的来源可进入自动批量采集。

退出标准：印尼不少于20个准入候选，比较国每国不少于8个候选，核心数据域均有
可执行来源和替代源，合规负责人签署准入决定。

## 4. 阶段三：D2 原始资料采集

1. 建立不可变批次号、任务号、请求参数和运行日志；
2. 保存原始网页/API/PDF/表格、响应头、抓取时间、哈希和来源版本；
3. 对失败、403、分页中断、字段漂移和访问限制进入异常台账；
4. 对敏感或无再分发权原件实施隔离和最小权限；
5. 完成五国最低样本目标，不以不可追溯记录凑数。

退出标准：原始包、清单、哈希和运行日志完整，采集可重放，无绕过访问控制行为。

## 5. 阶段四：D3 清洗与结构化

1. 解析语言、字段和原文定位，保留源文与译文绑定；
2. 标准化单位、币种、时区、日期精度和枚举；
3. 执行实体解析、确定性去重、模糊候选人工确认和可撤销合并；
4. 记录冲突事实、来源优先级、版本和变更原因；
5. 将失败记录留在候选区，不进入发布区或AI索引。

退出标准：映射可重放，所有候选有来源、版本和权限元数据，冲突与合并均可审计。

## 6. 阶段五：D4 审核、种子库与移交

1. 执行schema、必填、枚举、唯一、引用、日期、许可、时效和权限规则；
2. 对关键字段执行双人抽样，形成准确率和一致性报告；
3. 发布已审核种子数据，演练导入、重建、回滚和来源撤权；
4. 生成RAG候选，但只有已发布且有AI使用权的内容可进入索引；
5. 完成V0.1真实数据移交演练和D4正式评审。

D4硬门：

- 总分不低于85，且每个维度得分率不低于70%；
- P0数据问题为0；
- 印尼核心字段完整率不低于90%，四个比较国各不低于70%；
- 已发布关键事实可追溯率100%；
- 抽样准确率不低于95%，重复有效记录率不高于1%；
- 项目委员会完成D4批准签署。

## 7. 阶段六：V0.1 工程骨架

D4通过后才能执行：

1. 按冻结单仓结构建立 `apps/web`、`apps/admin`、`services/api`、
   `services/worker`、`packages/api-client`、`packages/ui`、`packages/config` 和
   `infra`；
2. 前端采用 Node.js 24 LTS、Next.js 16 App Router、React 19、TypeScript严格模式和
   Ant Design；
3. 后端采用 Python 3.13、FastAPI 0.139兼容线、Pydantic 2、SQLAlchemy 2和Alembic；
4. 建立 PostgreSQL 18、pgvector、OpenSearch 3.7、Redis 8.8、Celery 5.6和S3兼容
   对象存储的本地环境；
5. 直接导入D4已审核种子数据，完成登录、企业上下文、国家基础查询、OpenAPI客户端、
   审计、可观测和CI；
6. 以真实种子数据完成契约、权限和端到端验证。

## 8. 阶段七：V0.5 P0 情报与AI内测

按纵向闭环交付：

1. 国家列表、国家详情和2—4国比较；
2. 政策、风险、项目、招标和伙伴列表/详情；
3. 收藏、项目详情申请、伙伴对接、咨询和撮合申请；
4. 运营审核后台、发布、下架、纠错和索引失效；
5. AI出海顾问、会话历史、权限前置检索、SSE、引用、时效和拒答；
6. 真实种子用户完成“选国家—看风险—看机会—AI分析”的内测。

退出标准：核心旅程可用，阻断缺陷为0，权限泄漏为0，AI高风险无来源结论为0。

1. 报告模板、创建、异步任务、预览、文件、额度回滚和版本冻结；
2. 企业成员、角色、会员权益、额度流水、个人安全和同意偏好；

6. 全量单元、契约、集成、E2E、数据、AI、权限、安全、性能、兼容和UAT。

最终退出标准：

- 90项P0需求实现率100%，P0测试用例100%通过；
- S0/S1缺陷为0；
- P0关键任务成功率不低于95%；

- ACC-001至ACC-011全部完成证据与签署；
- 形成可构建、可部署、可回滚、可恢复和可移交的版本。

## 10. 提交与发布策略

每个提交只完成一个可验证目标，并同时更新测试、合同和文档。阶段门未通过时不创建
虚假的“完成”提交；任何P0范围、技术栈、权限、数据来源或AI边界变更必须走正式
变更评审。通过最终验收后再标记V1.0版本并推送受保护主线。
