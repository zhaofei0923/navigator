# i18n.md — 国际化（中英双语）规范

> 本文件是全平台**国际化（i18n）的唯一规范来源**，落实 AGENTS.md 第 7 节。
> 双语分两层：**UI 文本**（静态界面文案，走 i18n key）与**业务数据文本**（`LocalizedText`，见 [data-schema.md](./data-schema.md)）。二者不得混淆。

---

## 0. 总则

1. 支持语言固定为 `zh-CN`（默认）/ `en`（一等公民）。新增语言必须先在 [data-schema.md §1.1](./data-schema.md) 登记。
2. **禁止硬编码任何中英文字符串**到组件/接口中。UI 文案一律走 i18n key，业务展示文本一律用 `LocalizedText`。
3. 中英文案**必须同时补齐**；英文暂未确定时用占位并在 PR 标注待译，**不得只加一边导致 key 缺失**。
4. 默认语言 `zh-CN`；未识别到用户偏好时回退默认语言。

---

## 1. 两层双语的边界

| 维度 | UI 文本 | 业务数据文本 |
|------|---------|--------------|
| 例子 | 按钮、导航、表单标签、占位提示、错误提示 | 国家名、政策标题/正文、风险描述、报告摘要 |
| 存储 | `locales/{zh-CN,en}.json` | 数据库 `LocalizedText`（`{ zh, en }`） |
| 读取 | i18n 库（`t('key')`） | `pickLocale(text, locale)`（见 §5） |
| 归属 | 前端代码仓 | 数据库 / seed |

> 判断准则：**内容随部署固定、与国家数据无关** → UI 文本；**内容是国家业务数据的一部分、随数据更新** → 业务数据文本。

---

## 2. 技术方案

| 端 | 方案 | 说明 |
|----|------|------|
| Web（`apps/web`） | `next-intl`（App Router） | 统一方案，URL 前缀 `/[locale]/...` |
| Admin（`apps/admin`，Refine） | 与 Web 同一套 key 命名与文案 | 复用 `locales/` |
| 小程序 / H5（`apps/mini`，Taro） | Taro 对应 i18n 方案 | **key 命名与文案内容必须与 Web 两端一致** |

> 不同端可用不同 i18n 库，但 **key 集合与文案内容必须一致**（AGENTS.md §7.1）。

---

## 3. 语言包文件

### 3.1 位置与拆分
- 每端 `locales/` 目录下按语言拆分：`locales/zh-CN.json`、`locales/en.json`。
- **两个语言的 key 集必须完全对齐**，不得只加一边。
- 大型模块可用嵌套命名空间拆分文件（如 `locales/zh-CN/country.json`），但 zh/en 结构须镜像一致。

### 3.2 key 命名约定
- 命名风格：`camelCase`，用 `.` 分层：`{域}.{子域}.{语义}`。
- 域前缀建议：`common`（通用）、`nav`（导航）、`country`（国家页）、`ai`（顾问）、`coverage`（覆盖等级）、`lead`（留资）、`report`（报告）、`error`（错误提示）、`auth`（登录会员）；`compare`（对比）为 Deferred 能力，恢复时再启用。
- 禁止把可读英文短语直接当 key（如 `t('Click here')`），必须语义化：`t('common.clickHere')`。

**示例（片段）**：
```json
// zh-CN.json
{
  "common": { "loading": "加载中…", "notTranslated": "未翻译" },
  "coverage": { "dataBuilding": "数据建设中", "updating": "持续更新中",
    "level": { "BASIC": "基础覆盖", "STANDARD": "标准覆盖", "COMPLETE": "完整覆盖" } },
  "ai": { "noData": "暂无数据", "buildingHint": "该国数据建设中，暂无法提供深度问答" }
}
```
```json
// en.json
{
  "common": { "loading": "Loading…", "notTranslated": "Not translated" },
  "coverage": { "dataBuilding": "Data Building", "updating": "Continuously updating",
    "level": { "BASIC": "Basic", "STANDARD": "Standard", "COMPLETE": "Complete" } },
  "ai": { "noData": "No data available", "buildingHint": "Data is being built for this country" }
}
```

### 3.3 固定文案清单（跨文档引用的 key）
以下 key 被其他规范引用，必须存在且中英对齐：

| key | 用途 | 引用来源 |
|-----|------|----------|
| `common.notTranslated` | 业务文本降级标记 | data-schema §2.1 |
| `coverage.dataBuilding` | 模块建设中占位 | coverage-levels §4 |
| `coverage.updating` | 部分覆盖更新标记 | coverage-levels §4 |
| `coverage.level.*` | 覆盖等级徽章 | coverage-levels §4 |
| `ai.noData` | AI 无数据回答 | api-contract §5 |
| `ai.buildingHint` | BASIC 国家 AI 提示 | coverage-levels §5 |
| `error.*` | 错误码对应文案 | api-contract §0.4 |

## 4. 业务数据文本（LocalizedText）

- 类型定义与读取工具统一放 `packages/shared-types`，禁止各端重复定义：
  - 类型 `LocalizedText`、`Locale`
  - 工具 `pickLocale(text, locale)`：见 §5
- 接口返回按 `textMode` 处理拍平/原样（见 [api-contract.md §0.2](./api-contract.md)）。

---

## 5. 读取与降级（pickLocale）

统一降级逻辑，禁止在各处自行实现分支：

```ts
// packages/shared-types
export function pickLocale(
  text: LocalizedText | undefined | null,
  locale: Locale,
): { value: string; fallback: boolean } {
  const primary = text?.[locale === 'zh-CN' ? 'zh' : 'en'];
  if (primary && primary.trim()) return { value: primary, fallback: false };
  const other = text?.[locale === 'zh-CN' ? 'en' : 'zh'];
  if (other && other.trim()) return { value: other, fallback: true }; // 降级
  return { value: '', fallback: true };
}
```

**降级展示规则**：`fallback === true` 时，前端在文本旁标注 `common.notTranslated`（不得报错/空白）。接口 `localized` 模式下将该字段路径写入 `_i18nFallback`（见 api-contract §0.2）。

---

## 6. 语言切换与持久化

- 用户语言选择可切换并持久化，优先级：**URL 前缀 > Cookie/用户偏好 > `Accept-Language` > 默认 `zh-CN`**。
- Web 使用 `/[locale]/...` 路由前缀；切换时保持当前路径。
- 切换语言时，**UI 文案与业务数据文本同步切换**（业务文本通过重新请求或客户端 `pickLocale` 重取）。
- AI 顾问回答语言必须与当前界面/提问语言一致（AGENTS.md §9）。

---

## 7. 测试要求（配合 [testing.md](./testing.md)）

- **key 对齐测试**：校验 `zh-CN.json` 与 `en.json` 的 key 集完全一致（含所有端）。
- **降级测试**：`pickLocale` 在缺 zh / 缺 en / 全缺三种情况下的回退与 `fallback` 标记。
- **切换测试**：E2E 验证语言切换后 UI 文案与业务数据同步变化。
- **AI 语言一致性测试**：中文问→中文答，英文问→英文答。

---

## 8. 一致性检查清单

- [ ] 无硬编码中英文字符串（UI 走 key，数据走 `LocalizedText`）
- [ ] `zh-CN` / `en` 两个语言包 key 完全对齐
- [ ] 新增功能中英文案同时补齐（待译已标注）
- [ ] `LocalizedText` 类型与 `pickLocale` 仅定义于 `packages/shared-types`
- [ ] 降级标注走 `common.notTranslated`，不报错/空白
- [ ] 语言切换持久化且 UI 与数据同步
- [ ] 附 key 对齐 / 降级 / 切换 / AI 语言测试
