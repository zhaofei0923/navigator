> 文档状态：第三篇已确认。

> 本章承接第5—17章已确认的业务架构与产品需求，定义V1.0各终端的信息架构、菜单、路由、页面编号、页面权限及验收口径。本章页面清单是原型设计、前端路由、权限配置、接口联调、埋点和测试用例的共同基线。

### 18.1 平台信息架构

#### 18.1.1 信息架构目标

平台信息架构应支持用户从“发现市场”到“形成服务需求”的连续路径，并确保同一国家、政策、风险、项目、伙伴、报告和申请在不同终端使用同一业务实体和稳定标识，不得因终端不同而建立重复数据。

信息架构遵循以下原则：

1. **任务优先**：一级导航围绕选国家、看政策风险、找机会、找伙伴、使用AI、生成报告和跟进申请等核心任务组织。
2. **国家为主线**：国家是市场、政策、风险、项目、伙伴和报告的重要关联入口，但各专业模块仍保留独立检索入口。
3. **事实与生成内容分离**：结构化事实、来源原文、平台研判、AI生成内容和用户私有资料分别展示与存储。
4. **公开区与工作区分离**：公开页面承担认知和获客；登录后的企业工作区承担收藏、画像、AI、报告、申请和企业协作。
5. **前台与后台分离**：用户端不得暴露采编草稿、内部评分过程、商务备注、审核意见和技术配置。
6. **权限前置**：菜单可见、页面可访问、操作可执行、字段可查看、文件可下载和AI可检索分别校验，不能以隐藏前端组件代替服务端授权。
7. **多端复用**：PC Web、H5、小程序和后台共用稳定业务ID、统一API契约、状态枚举和权限服务。
8. **可扩展**：V1.0中文界面下预留英文名称、区域站点和多语言路由扩展能力，但不建设独立海外多语言站。

#### 18.2.5 H5、公众号与小程序菜单

H5不设置复杂多级菜单，底部或页面头部只保留“看国家、找机会、领报告、活动、我的申请”等轻量入口。公众号菜单使用受控短链跳转至H5或PC Web，并保留渠道参数。

小程序P1建议采用四个底部标签：“首页”“国家”“服务”“我的”。“服务”聚合活动报名、报告领取和申请进度，不在小程序内复制PC Web完整模块。

所有标注P1的菜单和子入口只有在相应feature flag、页面状态和权限同时启用时才显示；P0版本不展示不可操作占位，也不以“敬请期待”入口替代明确范围边界。

### 18.3 页面路由

#### 18.3.1 路由命名规范

1. PC Web采用无中文的小写复数名词路由，例如/countries、/policies。
2. H5统一使用/m前缀；运营后台统一使用/admin前缀；CRM统一使用/admin/crm前缀。
3. 路由参数使用稳定代码或不透明业务ID，不使用名称、手机号、邮箱、企业名称等敏感信息。
4. 国家路由参数使用平台稳定国家代码:countryCode；其他业务对象使用:id。
5. 同一对象只有一个规范详情路由。旧链接、短链或别名应通过服务端重定向到规范路由。
6. 路由不得携带访问令牌、会员等级、内部评分、联系方式或完整查询正文。
7. 列表筛选使用查询参数，详情对象使用路径参数；临时弹窗状态不作为永久分享链接。
8. 页面刷新、浏览器前进后退和直接粘贴链接必须恢复当前页面及可恢复的筛选状态。

#### 18.3.2 路由前缀

| 路由前缀 | 终端 | 示例 |
|---|---|---|
| / | PC Web公开区 | /countries |
| /auth | PC账号与认证 | /auth/login |
| /workspace | PC个人与企业工作区 | /workspace/requests |
| /m | H5 | /m/countries/:countryCode |
| /admin | 统一运营后台 | /admin/countries |
| /admin/crm | CRM | /admin/crm/leads |
| pages/ | 微信小程序 | pages/country/detail |

#### 18.3.3 标准查询参数

| 参数 | 用途 | 规则 |
|---|---|---|
| q | 关键词 | 长度受限，后端执行安全过滤 |
| page、page_size | 分页 | 使用统一默认值和最大值 |
| sort、order | 排序 | 仅允许白名单字段 |
| region、country、technology | 标准筛选 | 传稳定枚举代码，不传显示名称 |
| status、stage、risk_level | 状态筛选 | 与数据字典一致 |
| view | 列表或地图视图 | 仅允许定义值，如list、map |
| tab | 详情页标签 | 只用于页面内定位，不决定权限 |
| return_to | 登录/授权后的受控返回目标 | 必须校验站内白名单并使用签名或服务端会话绑定；全文不再使用`from`作为返回参数 |
| utm_*、channel_id | 渠道归因 | 只影响归因，不影响数据权限 |
| compare | 国家对比集合 | 使用国家代码并限制为2—4国 |

列表筛选状态应写入URL，以便刷新和分享；用户个人保存的筛选视图另存为后台记录。包含个人私有条件或受限对象的链接不得公开分享。

#### 18.3.4 路由守卫顺序

受限页面的路由守卫按照以下顺序执行。企业、会员、逐项审批等仅在目标资源声明适用时校验；不适用维度按中性通过处理，不得把“无企业”或“无逐项审批记录”错误解释为拒绝：

1. 检查页面是否存在及版本是否启用；
2. 检查登录状态和账号状态；
3. 对需要企业上下文的资源，检查企业归属、企业认证和企业状态；
4. 检查角色对页面及资源的基础权限；
5. 对受权益控制的资源，检查会员权益、额度、国家范围和有效期；
6. 对需审批或含敏感字段的资源，检查单次申请授权及字段级权限；
7. 加载业务数据并执行服务端过滤；
8. 记录访问、拒绝结果及必要审计事件。

未登录访问可恢复页面时，跳转登录并保存经签名的站内返回地址；登录后返回原目标。账号停用、企业暂停、权益不足、逐项审批不足和对象不存在必须使用不同的业务状态，不得全部显示为“页面不存在”。

#### 18.3.5 通用异常路由

| 状态 | 页面行为 |
|---|---|
| 401未登录 | 跳转登录，保留安全返回地址 |
| 403无权限 | 说明受限原因类别，展示申请或联系入口，不披露受限字段是否存在 |
| 404不存在 | 展示返回上级入口；仅在FR-IA-003的P1全局搜索启用时显示搜索，不泄露内部对象ID |
| 410已下架或失效 | 说明对象已失效，必要时展示替代记录 |
| 429额度或频率限制 | 展示剩余额度、恢复时间或升级入口 |
| 5xx系统异常 | 返回请求关联ID、重试入口和帮助渠道，不展示技术堆栈 |
| 数据为空 | 区分“暂无数据”“尚未覆盖”“筛选无结果”和“无权限” |

### 18.9 页面与权限对应关系

#### 18.9.1 权限模型

页面授权不使用单一“会员等级”判断，而采用“基础条件＋资源适用条件”的交集：

最终授权 = 账号状态 ∩ 角色权限 ∩ applicable（企业范围、会员权益、字段敏感级别、单次审批、对象状态）

`applicable`表示只评估目标资源声明适用的维度；不适用维度按中性通过处理。例如，无企业的注册用户仍可使用注册级国家对比和免费AI额度，只有企业私有文件、企业权益或需企业认证的申请才强制企业上下文。

页面权限至少分为五层：

| 层级 | 控制对象 | 示例 |
|---|---|---|
| 菜单权限 | 是否显示入口 | 无CRM权限不显示CRM菜单 |
| 页面权限 | 是否可进入路由 | crm.lead.read |
| 操作权限 | 是否可执行按钮或API | 编辑、审核、发布、导出、转派 |
| 数据范围 | 可以访问哪些记录 | 本人、企业、团队、区域、授权领域 |
| 字段/文件权限 | 可以查看哪些字段或附件 | 联系方式、合同依据、招标附件、内部评分 |

菜单隐藏、按钮禁用和字段掩码只用于交互提示；真正授权必须在API、搜索索引、缓存、导出、文件下载和AI检索层统一执行。

#### 18.9.2 用户端角色与页面范围

用户端基础身份代码如下：

#### 18.9.4 页面权限实现要求

1. 前端路由元数据必须保存page_id、permission_code、auth_required和entitlement_code，但前端判断仅用于导航体验。
2. 后端每个接口必须声明资源、动作、数据范围和字段过滤策略；不得只依赖页面权限。
3. 页面同时调用多个接口时，每个接口独立授权。页面可以打开不代表页面内所有卡片和字段均可访问。
4. 列表总数、聚合统计、搜索建议和导出任务同样执行权限过滤，防止通过数量或名称推断受限对象。
5. 用户权限变化后，应使相关缓存、签名下载链接、搜索结果和AI检索权限在规定同步时间内失效。
6. 逐项审批必须限定用户或企业、目标对象、开放字段、允许动作和有效期。
7. 403页面不得暴露受限字段确实存在；权益不足可展示产品或申请入口，但不能将其描述为系统故障。
8. 后台系统管理员的技术角色与业务数据角色分离；排障访问敏感数据需临时授权、审批和审计。
9. 所有敏感查看、文件下载、批量导出、发布、下架、角色变更、会员变更和模型切换必须记录操作日志。
10. 自动化测试须覆盖直接调用接口、修改路由参数、跨企业ID替换、过期授权、缓存残留和文件链接转发等越权场景。

#### 18.9.6 页面变更管理

新增、合并、拆分或下线页面必须更新页面台账，并评估以下影响：

- 菜单和路由兼容；
- 角色、权益、数据范围和字段权限；
- API、搜索、导出和AI检索；
- 埋点、渠道归因和CRM来源页面；
- 原型、测试用例、帮助内容和用户培训；
- 旧链接、收藏、报告引用和审计记录。

已使用的页面编号不得删除后复用。下线页面保留编号并标记retired，旧路由应根据业务情况重定向到替代页面或返回明确的410状态。V1.0需求冻结时，所有P0页面必须达到“页面编号已分配、路由已冻结、权限已定义、接口已映射、验收用例已建立”的开发准入条件。

附件D中的页面定义已完成文档审核并纳入V1.0-BASELINE，但文档确认不等同于页面已开发或已满足开发准入。附件D继续以“追踪状态”逐页标识需求、API、测试、埋点、原型和缺陷关联；依赖API、可执行测试、正式原型或设计稿编号尚未补齐的页面，追踪状态保持“待开发准入”。只有对应契约、用例和设计交付完成并通过准入检查后，方可把相应P0页面更新为“已冻结”或进入实现。

## 第19章 用户流程与交互规范

本章把第5—17章的业务要求转化为可执行、可恢复、可测试的用户流程。交互层负责引导、反馈和状态呈现，不自行计算机会等级、风险等级、核实状态、会员权益或字段权限；页面展示结果必须以业务服务返回的状态、枚举、权限和数据版本为准。

V1.0以PC Web企业工作台为主产品，H5承担公开内容浏览、轻量查询、活动承接和线索表单；微信小程序属于P1。三端共享账号、业务对象、API、状态枚举和埋点口径，不允许为移动端另建含义不同的业务状态。用户从H5进入需要深度分析的能力时，系统应保留合规的渠道参数和目标对象，引导其在PC Web继续操作。

所有核心流程遵循以下原则：

1. 主路径、权限不足、数据缺失、网络失败、并发冲突和人工复核均须有明确出口，不出现无说明的空白页或死循环。
2. 筛选条件、对象标识和非敏感页面状态尽量写入URL，便于返回、刷新和分享；访问令牌、联系方式、企业画像、受限字段和临时下载地址不得写入URL。
3. 创建、提交、审批、导出和AI调用等写操作使用幂等键；页面在请求期间阻止重复提交，但不得仅依赖按钮禁用保证幂等。
4. 用户离开含未保存内容的页面前应获得提示；可安全恢复的普通草稿保存至服务端，认证材料、敏感附件和AI受限内容不得写入不受控的浏览器持久缓存。
5. 任何推荐、AI回答和报告均区分结构化事实、平台评价、AI推断与行动建议，并展示来源、数据更新时间、适用范围和必要的人工复核提示。

### 19.1 注册及企业画像流程

注册及企业画像采用“先建立可恢复账号，再逐步完善企业上下文”的渐进式流程。用户可先注册并使用公开或注册级能力；只有在申请项目敏感详情、伙伴对接、企业会员权益或其他受限服务时，才按规则要求加入企业、完善画像或完成企业认证。系统不得把“企业画像未完善”显示成“企业未认证”，也不得把认证通过解释为平台对企业资信和履约能力的担保。

标准主流程如下：

| 阶段 | 用户操作 | 系统处理与页面反馈 | 失败或中断处理 |
|---|---|---|---|
| 进入注册/登录 | 选择手机号、邮箱；P1可选择第三方登录 | 说明用途、协议版本和隐私政策；保留安全的`return_to`目标 | `return_to`只允许站内白名单路径；非法或过期目标返回工作台首页 |
| 身份验证 | 获取并填写验证码，或输入密码 | 显示剩余有效时间、重发倒计时和必要的安全校验 | 错误提示不暴露账号是否存在；达到频率或尝试上限时显示恢复时间及申诉入口 |
| 建立账号 | 同意协议并完成验证 | 创建或激活账号、建立可撤销会话，状态进入`active` | 服务端失败时保留非敏感输入并允许重试；不得重复创建用户 |
| 建立企业上下文 | 搜索已有企业、申请加入，或创建企业 | 按注册号、注册地及标准名称查重；解释“加入”和“新建”的差异 | 命中疑似重复时提供申请加入或提交人工核验，不允许绕过查重建立重复主体 |
| 完善基础画像 | 选择企业类型、技术方向、出海阶段、目标国家/区域和需求 | 分组呈现字段，显示完成度和推荐用途；允许目标国家选择“待评估” | 可跳过非必要字段；缺少个性化条件时只给通用结果并提示完善，不阻断基础浏览 |
| 企业认证 | 企业管理员按需提交主体字段和证明材料 | 显示材料用途、访问范围、审核状态和预计处理方式 | 驳回时展示可公开的标准原因及补充入口；敏感内部意见不向申请人展示 |
| 完成与回流 | 确认画像摘要并进入原目标页面 | 生成画像版本，刷新推荐和权限，回到触发注册的安全目标 | 原目标已下架或权限仍不足时说明原因，并提供可执行的替代入口 |

账号状态沿用第7章的`pending_verification`、`active`、`locked`、`suspended`和`closed`。企业认证状态沿用`unverified`、`pending`、`verified`、`rejected`、`change_review`和`suspended`。页面必须显示状态名称、原因摘要、允许动作和下一步，不用一个“认证失败”覆盖所有状态。

企业画像表单按“主体信息、业务身份、技术能力、出海画像、联系信息”分组。主体关键字段变更触发复核；业务方向和目标市场等运营画像保存新版本后即时生效。自报信息、平台核验信息和公开来源信息分别标识为`self_declared`、`platform_verified`和`external_public`，不得在卡片、AI上下文或报告中混用来源性质。

交互要求如下：

- 必填项在标签中持续标识，不以提交后突然出现的错误代替事前说明；非必填项不得伪装成必填。
- 登录拦截弹层只用于轻量身份确认；需要多步骤注册、企业创建或认证时跳转独立页面，并保存原操作上下文。
- 邀请加入企业、申请加入企业和创建企业是三种独立动作。用户同一时刻只有一个前台当前企业上下文，切换后须重新加载收藏、报告、额度和权限。
- 企业资料的“保存草稿”和“提交审核”分开。提交审核前显示本次将锁定或进入复核的字段，提交成功后展示申请编号和状态入口。
- 用户刷新或重新登录后应从服务端恢复普通画像草稿；本地只保存草稿标识，不长期保存营业执照、联系人证件等敏感内容。
- 登录、身份绑定、密码重置、企业管理员变更、认证提交和主体字段变更均须产生可追溯审计事件。

验收时至少覆盖新用户注册、已有用户登录、验证码过期、账号锁定、疑似重复企业、申请加入、创建企业、认证驳回重提、主体信息变更复核、企业上下文切换以及从受限页面登录后正确回流等场景。

### 19.2 国家筛选流程

国家筛选由全球地图和国家列表共同承载，两者使用同一查询条件和结果集合。地图用于区域认知，列表用于精确筛选、排序和无障碍访问；任何地图交互均须在列表中存在等效操作。国家未纳入覆盖、字段暂无数据或用户权限不足是三种不同状态，均不得按“低机会”或“高风险”处理。

标准流程为“进入国家导航—选择主题和筛选条件—查看结果—检查数据质量—打开详情或加入对比—收藏/关注—进一步调用AI或报告”。查询状态由以下要素组成：关键词、区域、技术方向、机会等级、风险等级、政策友好度、数据覆盖等级、更新时间范围、排序方式和是否启用个性化。

| 交互节点 | 规则 | 页面反馈 | 可测试结果 |
|---|---|---|---|
| 初次进入 | 默认展示已发布国家，地图只启用一个主题图层 | 显示结果总数、当前图层、数据截止提示和推荐筛选入口 | 地图与列表国家集合一致 |
| 输入关键词 | 匹配中文名、英文名、ISO代码和已配置别名 | 提供自动完成并标明国家/区域；回车执行完整搜索 | 同一国家别名不形成重复结果 |
| 设置筛选 | 多选项按组处理，组内通常为“或”、组间为“且” | 已生效条件显示为可逐个移除的筛选标签，并提供“清除全部” | 刷新、前进和后退后状态可恢复 |
| 切换图层 | 机会、风险、覆盖等级一次只显示一种 | 同步更换图例和说明；未覆盖区域使用中性灰 | 风险色与机会色不混用含义 |
| 排序 | 默认可用平台推荐；另提供机会、风险、更新时间和名称等确定性排序 | 个性化排序须标明“基于企业画像”，并允许关闭 | 关闭个性化后返回确定性结果 |
| 查看摘要 | 悬停或聚焦地图、选中列表行或国家卡片 | 展示国家、主要指标、覆盖等级、最近综合复核时间和详情入口 | 键盘操作可得到与鼠标等价信息 |
| 深入操作 | 打开详情、加入对比、收藏或关注 | 权限不足时在动作发生点说明条件，登录后回到原对象 | 不因登录跳转丢失已选国家和筛选条件 |

筛选条件写入URL时使用稳定代码，不使用显示文案；停用字典项进入历史链接时，页面应显示“条件已停用”并允许一键移除。分享链接只包含公开查询条件，不携带企业画像、个人偏好、临时权限或受限数据快照。

列表中每个国家至少展示国家名称、区域、机会等级、风险等级、政策友好度、数据覆盖等级、最后复核时间和主要技术机会摘要。风险统一显示低、中、高、极高四级并配文字；“未评估”“数据不足”和“权限受限”不使用四级风险标签。平台评价应能打开方法说明或构成摘要，前端不得根据已展示字段自行重新计算等级。

筛选无结果时，页面应保留全部条件并说明导致范围收窄的条件，提供“移除最近条件”“清除全部”和“提交希望覆盖国家”等动作。接口部分失败但存在上次成功结果时，可保留旧结果并显著显示“数据可能不是最新”及重试入口；不得将缓存结果静默当作当前数据。

H5显示公开国家摘要、关键词/区域/技术方向等核心筛选和详情跳转，不承担复杂多维筛选的全部能力。需要国家对比、深度数据或报告时，引导至PC Web并保留国家代码和公开筛选条件。

### 19.3 国家对比流程

V1.0一次对比2—4个已发布且至少达到Basic覆盖的国家。少于2个时可以维护选择但不能生成正式对比；达到4个后继续添加时应提供“替换现有国家”或“新建一组对比”，不能静默删除最早选择。国家按ISO代码去重，用户可调整列顺序，顺序变化不改变数据快照。

对比流程如下：

1. 用户从国家列表、详情、收藏或历史记录把国家加入对比托盘。
2. 系统持续显示已选数量、国家名称、移除和排序动作；选择不足或超限时在托盘内直接解释。
3. 用户选择一个主技术方向或“国家综合”，确认比较时间范围和指标组。
4. 系统校验国家发布状态、用户权限、指标定义和可比性，创建对比会话及数据快照。
5. 页面先返回结构化对比矩阵，再按需加载趋势、来源和解释；AI不可用时结构化对比仍须完整可用。
6. 用户可查看指标定义、原值/换算值、来源、更新时间和缺失原因，并按权益选择AI辅助解释。保存、受控分享和版本化对比报告属于FR-COMPARE-007/008的P1能力，未启用时不出现在P0主路径。

每个对比单元格至少消费`value`、`display_value`、`unit`、`period`、`value_type`、`source_ids`、`freshness`、`quality_status`和`permission_status`。页面不得用短横线统一代替不同状态，须使用以下可理解文案：

| 数据状态 | 展示文案 | 交互行为 | 禁止行为 |
|---|---|---|---|
| 无记录或未采集 | 暂无数据 | 显示该指标定义及纠错/补充入口 | 当作0参与排序或评分 |
| 未达到评分条件 | 待评估 | 展示缺少的关键数据类型 | 用总体评分替代技术专项评分 |
| 超过复核周期 | 待更新 | 显示原统计期、最后复核时间和来源 | 隐去旧值后让用户误以为无数据 |
| 字段无权访问 | 权限受限 | 展示可公开的权限说明和申请入口 | 泄露数值、区间或字段是否存在的敏感细节 |
| 统计期/口径不同 | 口径不一致 | 并列原值、口径和期间，允许查看说明 | 直接得出高低结论 |
| 来源冲突 | 来源存在冲突 | 展示冲突来源、平台处理和待复核状态 | 只选择有利来源形成确定结论 |

页面固定显示比较范围、主技术方向、指标版本和数据截止时间。数值换算必须同时显示原值、换算值、单位、汇率或换算来源及基准日。预测值、目标值和历史实际值应使用文字标识，而不是只用颜色或线型区分。

AI辅助对比是结构化矩阵上的解释层。调用前把用户确认的国家、顺序、技术方向、时间范围和企业画像快照展示为上下文；输出必须包括关键差异、适配场景、风险与不确定性、来源和建议核实项。AI不得补齐缺失值、改变已审核等级或把当前2—4国的相对排序表述为全球结论。高/极高风险以及法律、税务、投资相关结论持续显示专业复核提示。

P1启用保存、受控分享或对比报告后，系统保存国家集合、顺序、指标版本、数据快照和创建者；后续数据更新不静默覆盖历史结果，而显示“有更新可用”并允许创建新版本。P1导出前重新校验权限，文件中保留数据截止时间、来源清单、缺失与不可比说明、AI参与说明和复核状态。P0结构化对比与AI解释不依赖上述P1能力。

验收至少验证2国、4国、少于2国、添加第5国、重复国家、国家下架、受限指标、缺失值、口径不一致、来源冲突、AI不可用、历史快照更新和导出时权限变化等场景。

### 19.4 项目查询流程

项目查询面向市场、销售、EPC、投资开发和项目人员，主流程为“检索/筛选—查看项目摘要—判断核实与时效—打开详情—收藏或申请敏感详情—形成跟进”。项目进入平台只表示其为可供研判的机会信息，不构成真实性担保、投资建议或中标承诺。

项目列表支持关键词、国家/区域、技术方向、项目类型、规模区间、项目阶段、招标状态、资金来源、发布时间、核实状态、机会等级、更新时间和是否有文件等筛选。关键词至少可检索项目名称、业主公开名称、招标编号和地点。筛选条件写入URL，但联系人、内部判断、未授权条件和临时文件地址不得进入URL。

项目卡片或列表行至少展示：项目名称、国家/地点、技术方向、规模及单位、项目阶段、关键日期、机会等级、核实状态、最近核实时间、主要风险提示和公开来源数量。以下三类信息必须在视觉和语义上分离：

| 信息类型 | 统一口径 | 交互要求 |
|---|---|---|
| 项目核实状态 | `unverified`待核实、`partly_verified`部分核实、`verified`已核实、`disputed`存在争议 | 始终显示文字和状态说明；可打开核实证据摘要 |
| 风险等级 | `low`低、`medium`中、`high`高、`critical`极高 | 显示风险类别、更新时间和来源；不以核实状态代替风险 |
| 独立风险标记 | 包括“高风险疑似虚假”等 | 使用强提示并说明依据及复核状态；不得混入四类核实枚举 |

项目详情采用统一模块：事实摘要、阶段时间线、参与方、招标信息、核实与来源、机会评价、风险提示、相关政策、附件和操作区。项目业务阶段、核实状态、采编发布状态、招标状态分别展示，不能把“已发布”误写为“已核实”，也不能因招标截止自动推断项目已中标或取消。

V1.0 P0只要求完成招投标列表、详情、公开/获准附件信息和项目申请流程；招标文件上传、自动解析、解析结果确认及基于解析结果的深度问答均为P1，不作为V1.0 P0上线验收条件。P0阶段应预留路由、权限、任务状态和企业私有文件隔离接口，但不得以未完成的P1解析能力阻断招投标信息查询。

关键日期同时显示时区和数据来源；即将截止、已截止、日期待确认采用不同文字状态。来源失效、状态争议或关键节点过期的项目保留历史记录，但默认结果中应降级或移出“当前可跟进”，并说明变化原因。用户收藏的项目被下架或更新时保留关联，显示状态变化而不是直接消失。

用户打开敏感联系方式、受限附件或深度研判时，由服务端返回可见字段、脱敏值或申请要求。无权限页面可展示获准的公开摘要及“申请项目详情”入口，不能通过HTML、接口错误、AI回答、导出文件或页面源数据泄露受限内容。外部文件和来源链接应标明发布机构、日期和访问风险，并在新窗口打开；下载受限文件前再次校验权限和有效期。

无结果时区分“筛选过严”“项目尚未覆盖”“数据暂不可用”和“因权限仅能看到部分结果”。H5只展示项目公开摘要、核实状态、最近核实时间、来源和风险提示；需要附件解析、敏感详情和深度跟进时转入PC Web或提交合规表单。

### 19.5 AI问答流程

AI问答是结构化数据、RAG知识库和规则服务的统一自然语言入口，不是独立事实来源。入口提供自由提问以及“选国家、国家对比、政策解读、找项目、看风险、找伙伴、进入策略、生成报告”等场景。用户可通过上下文标签明确国家、项目、技术方向、时间范围和企业画像；P0可检索平台已发布且用户有权访问的知识文档，企业私有招标文件仅在FR-OPP-005的P1上传解析能力启用后可选。系统不得在用户不知情时把其他会话、其他企业或后台备注加入上下文。

标准处理与交互如下：

| 阶段 | 系统动作 | 用户端呈现 | 关键控制 |
|---|---|---|---|
| 输入 | 接收问题、上下文和附件标识 | 显示已选择的国家/项目/文件和可移除标签 | 不在输入框或URL暴露其他企业信息；附件先完成安全和权限检查 |
| 预校验 | 校验账号与输入安全，并仅对任务声明适用的企业空间、会员额度和字段权限执行校验 | 权限或额度不足时在调用前说明，不启动完整模型任务；无企业注册用户仍可使用获准免费能力 | 权限不足不得透露受限内容是否存在；未开始的任务不扣额度 |
| 意图与风险识别 | 解析任务、实体、时间意图并判定普通/重要/高风险 | 必要时显示将使用的范围；高风险入口预先说明复核边界 | 不能因会员等级跳过风险分级 |
| 澄清 | 发现国家、技术、时间或目标不明确 | 一次提出最少必要问题，并保留原问题 | 状态为`need_clarification`；澄清前不消耗完整报告额度 |
| 检索 | 查询结构化服务和授权RAG，执行时效、来源、冲突和权限过滤 | 显示“正在检索”，可取消；不展示未经验证的中间结论 | 检索无证据时不得让模型自行补全事实 |
| 生成 | 基于证据集合生成并区分事实、评价、推断和建议 | 可流式展示已通过分片安全检查的草稿，并持续标识“生成中，尚未完成引用校验” | 任何越权片段须在送达客户端前拦截 |
| 校验 | 检查事实—引用支持关系、时效、权限、敏感内容和高风险提示 | 校验完成后才标记为最终回答 | 关键事实无引用时删除、降级或转人工复核，不得静默发布 |
| 完成与反馈 | 保存版本、消耗、引用、模型/Prompt和反馈 | 展示答案、引用、数据截止时间、局限、复核状态和下一步动作 | 重新生成创建新的`generation_id`，不覆盖旧版 |

用户端结果状态沿用第5章：`completed`、`completed_with_warning`、`need_clarification`、`insufficient_evidence`、`permission_denied`和`failed`。过程状态可显示已创建、检索中、生成中、待人工复核、已完成、部分完成、失败、已取消或已过期，但前端不得据此另建含义不同的业务枚举。

最终回答的固定结构至少包括：结论摘要、事实与依据、风险/不确定性、建议下一步、来源引用、生成时间和数据截止时间。引用在相邻事实处以编号显示，点击后打开来源抽屉，展示来源标题、发布机构、发布日期或统计期、最后核实时间、定位信息和访问状态；用户无权打开原文时只显示获准的来源元数据和权限说明，引用摘要不得泄露正文。

涉及“最新、目前、是否仍有效、是否截止”等问题时必须检查最新已授权来源。无法确认时明确写明“截至某日无法确认”，不能只依赖模型知识或旧对话。来源过期、失效或相互冲突时，回答使用`completed_with_warning`或`insufficient_evidence`，并列明已确认部分、冲突点和待核实项。

高/极高风险、法律税务、制裁与出口管制、重大投资、项目真实性争议、人身安全及正式投标关键事项，在回答顶部和相关结论处显示不可由用户关闭的复核提示。待人工复核时，可展示已核实事实、来源和补充材料清单，但不发布未经审核的确定性结论。提示应说明“为什么需要复核、由何种专业人员复核、当前可采取什么安全动作”。

用户取消任务后立即停止后续可取消调用，状态保留为已取消，并按额度规则释放预占。失败后“重试”沿用原问题和上下文但创建新的任务尝试，避免重复扣费。网络断开后允许重新连接到原`task_id`继续接收；服务端已完成时直接恢复最终结果，不重新调用模型。

P0每条回答只提供有帮助/无帮助的最小反馈事件，不形成可查询工单，也不自动触发完整纠错闭环；错误分类、工单历史、定位回答片段和回归处理在FR-AI-006的P1能力启用后提供。用户主动选择“联系顾问”并确认转交范围后，系统才可把需求摘要、目标对象、时间和对话ID写入CRM；完整对话默认不向商务开放，纯模型推测的意向不得自动建线索。

### 19.6 报告生成流程

报告中心支持国家市场简报、国家对比报告、政策影响分析、项目机会清单、风险初筛、伙伴候选清单和市场进入策略；“招标文件摘要”仅在FR-OPP-005的P1上传解析能力启用后提供，P0模板列表不得展示或选择该模板。报告生成必须复用与AI问答相同的权限、结构化查询、RAG、引用、时效和高风险控制，不得建立绕过校验的独立生成通道。

| 步骤 | 用户操作 | 系统处理 | 页面验收点 |
|---|---|---|---|
| 选择模板 | 查看模板用途、适用对象、复核级别和所需权益 | 只返回已发布且用户有权使用的模板版本 | 停用模板不用于新建，但历史报告仍能显示其版本 |
| 配置参数 | 选择国家、技术方向、时间范围、章节、企业画像和文件 | 校验必填项、对象权限及数据可用性；仅国家对比报告执行2—4国限制 | 参数摘要可检查和修改；推断标签不得未经确认写入正式报告 |
| 生成前确认 | 确认数据范围、预估额度、文件格式和免责声明 | 冻结模板、用户输入、数据版本、资料范围和权限快照 | 用户能看到将使用的主要来源范围和高风险复核要求 |
| 异步生成 | 提交并可离开页面 | 创建报告及任务，执行检索、生成、自动校验和必要的人工复核 | 列表持续显示进度、当前阶段、开始时间、取消或失败恢复动作 |
| 在线预览 | 查看章节、图表、引用、缺失说明和复核状态 | 按模板规则处理缺失章节，不由模型填补 | 每个关键事实可追溯；数据截止时间和AI参与说明可见 |
| 导出/发布 | 选择获准格式并下载或在企业空间发布 | 重新校验权限，生成文件版本和短时签名地址 | 文件含报告范围、生成日期、截止日期、来源清单、复核状态和免责声明 |

报告业务状态沿用第13章的草稿、生成中、自动校验中、待人工复核、退回修改、已完成、已发布、生成失败、已撤回和已归档。异步报告/文件任务严格沿用第14章已确认的`queued`、`processing`、`completed`、`failed`、`cancelled`和`expired`六态；人工复核只存在于报告业务状态，不另造任务状态。若后续另建`export_job`，须在第22章定义独立实体和枚举，不得临时使用未定义的`generating`或`review_required`。业务状态与任务状态在字段、文案和测试中分开，不能把“文件链接过期”显示为“报告生成失败”。

生成页面应显示阶段式进度而非不可信的精确百分比；只有后端能提供可验证工作量时才显示百分比。用户取消仅在任务允许取消时出现；进入不可撤销的人工复核或发布环节后，页面说明取消将转为撤回申请。因平台异常失败的任务释放额度或形成返还流水，恢复时从安全检查点重试，不重复创建报告。

预览中对无数据章节按模板配置显示“暂无数据”、隐藏或阻止完成，并明确原因。用户编辑标题、摘要或备注形成编辑版本，不覆盖原始AI稿和来源快照；结构化事实字段如需修改，应转数据纠错或创建带审计的人工修订，不允许直接在富文本中无痕改写。

报告完成后，如关键来源失效或底层数据更新，历史文件保持不变并显示“有更新可用”，用户可基于新快照生成新版本。分享链接默认关闭；启用时必须设置访问范围、有效期和撤销能力，不把会话凭证写入链接。下载前再次验证用户、企业、会员、字段和文件有效期，权限变化后旧签名链接立即失效或拒绝访问。

### 19.7 项目详情申请流程

项目详情申请用于受控开放项目敏感字段、附件或进一步服务，不等同于会员自动获得全部详情。入口在受限字段占位、项目操作区和会员权益说明中保持一致。提交前应展示当前可见内容、拟申请范围、审批用途和平台不对项目真实性作担保的说明。

申请表至少包含目标项目、申请目的、企业能力、联系人、预期参与方式、希望开放的资料范围和信息使用授权。企业画像已有且仍有效的字段可以预填，但须标明来源并允许用户确认；敏感联系人不得从其他申请或其他企业上下文自动带入。

申请状态和页面动作如下：

| 状态 | 用户端显示 | 申请人动作 | 运营/审核动作 |
|---|---|---|---|
| `draft`草稿 | 已保存、尚未提交 | 编辑、提交、删除 | 不进入正式审批队列 |
| `submitted`已提交 | 申请编号、提交时间和受理说明 | 在受理前按规则取消 | 受理、退回补充或确认取消 |
| `need_more_info`待补充 | 缺少材料及公开说明 | 补充后重提、取消 | 检查补充内容 |
| `under_review`审核中 | 当前环节和最近更新时间 | 查看状态；原则上不直接编辑 | 批准或驳回并记录依据 |
| `approved`已批准 | 开放范围、有效期和附加约束 | 在有效期内查看获准字段/文件 | 可按授权规则撤销或调整 |
| `rejected`已驳回 | 可公开的标准原因和重新申请条件 | 条件变化后发起新申请 | 保留内部审核意见和审计 |
| `cancelled`已取消 | 取消时间和发起方 | 只读 | 无 |
| `expired`已过期 | 原开放范围及到期时间 | 需要时重新申请 | 无 |

同一企业、同一项目、同一申请类型在配置的去重窗口内已有未关闭申请时，系统返回原申请并引导继续处理，不新增线索、不重复扣减额度。去重窗口建议默认7日、待业务确认后以规则版本配置；用户切换企业上下文时，正在填写的申请应提示重新校验；A企业草稿不能带入B企业提交。

批准不是一个永久布尔值。批准记录必须包含具体字段、附件、下载能力、有效期、用途和附加约束；页面只解锁服务端返回的授权范围。到期或授权撤销时即时恢复受限展示；会员状态变化时按批准记录、合同/后台配置和第14.9节规则重新计算有效授权，未完成的已批准服务不得被一刀切收回。所有变化均保留申请和访问历史。驳回原因使用标准原因加可选说明，不能向用户暴露安全策略、第三方非公开意见或敏感调查内容。

提交成功即创建或关联CRM线索；前台申请成功而CRM暂时失败时，申请仍保持成功并由可靠队列重试，不要求用户重复提交。P0以申请中心持续展示状态；站内消息中心PC-WRK-006在P1启用后提供补充提醒。外部短信、邮件或微信通知按用户授权和渠道配置执行，不作为P0流程的唯一通知方式。

### 19.8 伙伴对接流程

伙伴对接遵循“查看公开能力—提交合作诉求—平台核验与征得授权—双方同意披露—完成引荐”的流程。伙伴列表和AI建议只提供匹配解释，不把推荐等级显示为信用担保，也不在双方授权前公开个人联系方式。

用户提交对接申请时须确认目标伙伴、合作诉求、企业简介、联系人、计划时间、希望披露的资料和是否允许平台向伙伴转交。系统在确认页逐项列出“向伙伴披露的信息”和“暂不披露的信息”，用户未勾选授权的字段不得进入CRM摘要、通知内容或伙伴侧页面。

基础申请状态沿用项目详情申请，并在业务受理后增加`partner_contacted`已联系伙伴、`partner_accepted`伙伴接受、`partner_declined`伙伴拒绝和`introduced`已完成引荐。状态展示要求如下：

| 状态节点 | 申请方可见信息 | 联系方式处理 | 下一步 |
|---|---|---|---|
| 已提交/审核中 | 申请编号、诉求摘要、受理状态 | 双方联系方式均不新增披露 | 平台核验主体、用途和资料范围 |
| 已联系伙伴 | 已发出合规联系，不展示伙伴响应细节 | 仍不交换非公开联系方式 | 等待伙伴选择接受、拒绝或要求补充 |
| 伙伴接受 | 接受意向及双方获准的披露摘要 | 校验双方授权范围的交集 | 平台安排引荐或补充披露确认 |
| 伙伴拒绝 | “对方暂不接受本次对接”等中性结果 | 不披露伙伴非公开原因和联系人 | 结束本次申请或提供其他候选入口 |
| 已完成引荐 | 引荐时间、方式、平台责任边界 | 仅交换双方明确同意的字段 | 进入后续跟进，不自动标记合作成功 |

相同企业、伙伴和诉求在规定去重窗口内存在未关闭申请时，应回到原申请。伙伴被暂停、阻断、风险升级或联系方式失效时，系统暂停新的自动推荐和披露，向申请人说明可以公开的原因及替代动作；历史引荐记录不删除。

引荐完成只代表建立联系，不代表平台验证全部资质、保证履约或促成交易。后续合作状态由CRM或撮合流程管理，不从是否查看联系方式推断成交。用户撤回尚未发生的披露授权时停止后续转交；已经依法合规披露的历史记录按留存规则保留并显示撤回时间。

### 19.9 CRM跟进流程

CRM为平台内部商务和运营工作台，P0以PC Web后台为主，不在H5或小程序提供完整跟进能力。流程从申请或用户确认的高意向事件创建/关联线索开始，经过基础人工/规则分级、分配、接受、首次联系、资格判断、培育或转商机。行为评分模型和增强报表属于FR-CRM-003的P1能力；P0仅提供完成分配跟进所需的基础等级和最小运营看板。普通浏览和未经用户确认的AI对话不直接创建线索。

| 阶段 | 核心交互 | 状态或校验 | 异常处理 |
|---|---|---|---|
| 创建/关联 | 查看来源申请、企业、联系人和去重建议 | 同一请求ID只关联一次；可配置去重窗口按规则合并，建议默认7日、待业务确认 | 自动创建失败进入重试队列和异常看板，不丢失原申请 |
| 基础分级（P0） | 查看人工/基础规则形成的A/B/C/D等级和依据 | 保存规则版本；人工调整须填写原因和有效期 | 规则不可用时保留原等级并提示人工复核；行为评分模型在P1启用 |
| 分配 | 主管或规则按客户归属、区域、行业和负载分配 | 记录负责人、分配时间和首次响应SLA | 无匹配负责人进入公共池并告警；转派保留历史 |
| 跟进 | 记录方式、摘要、客户反馈、结果和下一步 | 必填下一步或关闭原因；敏感自由文本提示 | 保存失败保留草稿；重复请求使用幂等键 |
| 阶段流转 | 按允许路径从新建到联系、验证、培育或转商机 | 关键阶段检查准入条件 | 非法跳转在服务端拒绝并说明缺少条件 |
| 线索关闭/重开 | 选择无效、合规关闭或其他标准原因，对应`disqualified/closed` | “其他”必须补充说明；重开需相应权限 | 关闭不删除来源、跟进和阶段历史；不得使用商机成交/失败状态 |
| 商机关闭/重开 | 在商机记录中选择`won/lost/cancelled`并填写依据 | 成交、失败和取消分别校验；重开需主管权限 | 不把线索`converted`直接显示为成交，也不回写项目事实 |

线索列表支持负责人、团队、国家、行业、来源、等级、状态、下一步日期和创建时间筛选，并允许保存个人视图。默认视图突出我的待办、逾期任务、A/B类新线索、待联系申请和即将到期会员。P0最小看板只展示本人/团队待办、逾期和基础阶段数量；漏斗、渠道、团队与SLA增强报表在P1启用。列表批量分配、关闭、导出和跨团队转派属于增强权限操作，须显示影响数量、二次确认和结果明细。

线索详情用时间线统一展示来源事件、业务申请、分配、跟进、阶段、审批和商机关系。跟进记录保存后不可无痕覆盖；修改显示版本，删除采用逻辑删除及授权审批。多人同时编辑时使用版本号或ETag控制，服务端返回冲突后页面展示最新值与本人草稿，不得静默以最后提交覆盖他人工作。

敏感联系方式按角色和数据范围脱敏。点击“查看完整信息”、复制、导出或下载均应重新校验权限并记录审计；系统不得在列表预加载或前端状态中下发无权字段。主管可查看本团队，不因CRM管理员配置规则就默认获得所有企业对话、文件或完整联系方式。

状态沿用第15章：线索为`new`、`assigned`、`contacting`、`qualified`、`nurturing`、`converted`、`disqualified`和`closed`；商机为`discovery`、`solution`、`proposal`、`negotiation`、`on_hold`、`won`、`lost`和`cancelled`。页面动作由状态机返回，不在前端硬编码任意跳转。SLA倒计时按统一业务时区和工作日历计算，并显示截止时间，不仅显示颜色。

### 19.10 加载、空状态和错误状态

加载、空状态和错误状态是页面的正式组成部分，应在设计稿、组件库和测试用例中完整覆盖。任何状态都须回答“当前发生了什么、已有内容是否可信、用户现在能做什么、操作是否会丢失”。

| 状态类型 | 适用场景 | 标准呈现 | 恢复动作 |
|---|---|---|---|
| 首次加载 | 页面首次获取关键内容 | 使用与最终布局接近的骨架屏；表格保留表头结构，避免整页跳动 | 加载超时后转为明确错误，不无限旋转 |
| 局部加载 | 筛选、分页、收藏或单个模块刷新 | 保留页面上下文，在目标区域显示进度；不可操作项局部禁用 | 用户可取消的长任务提供取消入口 |
| 后台刷新 | 已有有效数据、正在获取新版本 | 保留旧数据并显示轻量刷新状态 | 刷新失败时标注“当前显示上次结果”及时间 |
| 初次空状态 | 用户尚无收藏、报告、申请或线索 | 解释功能价值并提供一个主要动作和必要示例 | 不用“暂无数据”代替新手引导 |
| 筛选无结果 | 数据库有内容但当前条件无匹配 | 保留筛选，列出已生效条件和结果数0 | 移除最近条件、清除全部或保存条件 |
| 业务未覆盖 | 国家、指标或项目尚未采集/发布 | 显示未覆盖、预计处理方式或反馈入口 | 不映射为0分、低机会或高风险 |
| 权限受限 | 用户无权查看对象、字段或动作 | 显示最小必要说明、所需条件和申请/登录入口 | 不泄露敏感内容存在性、数量或取值范围 |
| 部分失败 | 页面多个模块中仅部分服务失败 | 成功模块继续可用，失败模块独立说明 | 对失败模块重试，不强制刷新整页 |
| 页面级错误 | 关键服务失败、对象不可访问或系统异常 | 显示可理解文案、错误追踪号和安全返回路径 | 重试、返回列表、联系支持；保留未提交草稿 |
| 离线/网络中断 | 浏览器断网或请求中途失败 | 显示离线状态；只读缓存明确标注时间和非最新 | 恢复网络后由用户或系统安全重连原任务 |

常见HTTP/业务错误与页面行为统一如下：

| 错误类别 | 页面行为 | 数据与操作要求 |
|---|---|---|
| 401会话失效 | 提示重新登录并保存安全的返回路径 | 不保存密码、令牌或敏感表单到URL/普通缓存 |
| 403/受限访问 | 展示权限、权益或审批入口 | 不根据接口差异泄露受限对象是否存在 |
| 404/对象不存在 | 返回不存在页面并可回到所属列表；仅在FR-IA-003的P1搜索启用时提供搜索 | 不把“尚未发布/已下架”当作公开语义；为防枚举攻击而安全掩蔽的受限对象可返回相同外观，但不得写入“未公开”事实 |
| 410/已下架或失效 | 对有合法历史关联的用户说明记录已下架/失效并给出替代入口 | 仅展示获准的历史最小信息；公开访问不得泄露下架原因中的敏感内容 |
| 409并发或状态冲突 | 展示服务器最新状态与本地待提交内容 | 用户确认后重新应用，不自动覆盖 |
| 422字段校验失败 | 在字段旁显示服务端错误，并聚焦首个错误 | 已输入的合法字段不清空 |
| 429频率或额度限制 | 显示限制类型、可再次尝试时间和合规升级入口 | 不自动高频重试；额度流水可对账 |
| 5xx/依赖失败 | 提供重试和错误追踪号；必要时显示上次可信数据 | 写操作先查询幂等结果，避免用户重试产生重复记录 |

骨架屏只用于结构可预测的内容，未知时长后台任务使用阶段状态；不得用骨架屏伪装真实数据。按钮加载状态保留原宽度，文案改为“正在提交/生成/导出”等具体动作。超过一个页面区域的全屏遮罩只用于会导致数据冲突的短暂关键操作，普通加载不得阻断阅读已有内容。

错误信息不得直接展示堆栈、数据库字段、模型供应商密钥、内部URL或第三方原始异常。面向用户的错误码用于客服追踪，服务端日志保存完整技术上下文。自动重试仅用于安全、幂等且短暂的失败；非幂等提交、权限拒绝、字段错误和额度不足不自动重试。

### 19.11 表单校验与操作反馈

表单由统一Schema、数据字典和权限配置驱动。前端校验用于及时反馈，服务端校验是最终依据；两者使用相同字段代码和错误映射。动态必填、字段长度、枚举、单位、附件类型和业务条件不能分散硬编码在不同页面。

表单校验规则如下：

| 规则 | 交互要求 | 验收要求 |
|---|---|---|
| 标签与必填 | 每个控件有持久可见标签；必填、选填和用途明确 | 占位符不能作为唯一标签；屏幕阅读器可读名称一致 |
| 校验时机 | 首次输入时不过度打断；失焦后校验已编辑字段，提交时校验全部 | 纠正后错误即时消失；不在每个按键后弹出全局提示 |
| 格式与标准化 | 去除无意义首尾空格；保留企业法定名称等有意义字符；手机号、邮箱、URL按规则校验 | 原始输入与标准化值按数据规则处理，不由前端擅自改写法定内容 |
| 枚举与联动 | 使用后台字典代码；停用项在历史记录中可读但不能新选 | 条件字段隐藏时清理或明确保留其值，不能偷偷提交不可见旧值 |
| 数值与单位 | 标签中显示单位，必要时保留原值和换算口径 | 千位、小数、负数、上限、币种和时区按字段定义验证 |
| 日期与时区 | 明确日期格式、业务时区和起止关系 | 截止时间不能因浏览器本地时区静默改变业务含义 |
| 文件上传 | 上传前显示类型、大小、数量、用途和敏感提示；上传后显示安全扫描状态 | 扩展名和MIME双重校验；失败可单文件重试，不重复上传成功文件 |
| 隐私与授权 | 同意项按用途拆分，非必要营销授权不得与核心服务捆绑 | 保存授权文本版本、时间、对象和撤回记录 |
| 服务端错误 | 错误显示在对应字段，并提供页面顶部错误摘要 | 聚焦首个错误；不清空其他合法输入；未知错误提供追踪号 |

提交按钮使用明确动词，如“提交认证”“申请项目详情”“生成报告”，避免笼统“确定”。请求发出后按钮进入加载状态并阻止重复操作，页面保留内容；服务端以幂等键保证最终只产生一个结果。成功反馈同时包含短时提示和页面内持久状态，例如申请编号、报告任务或最新更新时间，不能只显示一闪而过的Toast。

收藏、关注等低风险可逆操作可以即时反馈并在失败时回滚；删除草稿、取消申请、撤回报告、批量关闭、跨团队转派等影响明显的操作须展示对象、影响和后果。可恢复删除优先提供撤销；不可恢复或会影响他人的操作需二次确认，确认按钮使用具体后果文案。

表单离开保护只在存在尚未保存的有效变更时触发。自动保存显示“保存中、已保存、保存失败”和最后成功时间，保存失败时不把本地内容标记为已保存。用户打开同一草稿的多个标签页时，检测版本冲突并提示选择最新服务端版本、保留本地副本或人工合并。

所有操作反馈须通过视觉、文字和可访问状态共同表达。错误摘要使用`aria-live`或等效机制通知辅助技术，焦点移动遵循用户预期；Toast不承载唯一关键内容。表单支持全键盘操作，逻辑顺序与视觉顺序一致，弹层关闭后焦点返回触发元素。

## 第20章 UI与前端设计规范

本章定义V1.0用户端与运营后台的视觉、组件、响应式和前端交付基线。规范用于产品原型、UI设计、前端实现、组件测试和验收，不替代第31—33章的工程选型。所有视觉令牌、组件状态和业务枚举应集中管理，页面不得复制一套近似颜色、文案或交互逻辑。

PC Web是V1.0主要生产力界面，设计优先保证大屏信息检索、对比、研判和报告工作效率；H5保证公开内容、轻量查询和线索承接；小程序仅做P1兼容预留。三个终端保持品牌、语义色、业务状态和基础组件行为一致，但不要求把PC复杂表格机械缩小到移动端。

### 20.1 视觉定位

平台视觉定位为“国际化、专业、可信、克制的企业级新能源出海情报与决策平台”。界面应体现数据证据、更新时间、风险边界和操作效率，不采用新闻门户式高密度堆叠，也不采用消费应用式夸张动效、卡通插画或无业务意义的3D装饰。

设计原则如下：

1. **证据优先。** 国家、政策、项目、伙伴、AI和报告页面均把来源、数据时间、核实状态和风险放在用户能够发现的位置。
2. **一屏一主任务。** 页面只设置一个明确的首要动作，首页或详情首屏通常突出3—5个关键信息组，次要信息按层级展开。
3. **低密度但不低效率。** 通过分组、留白、对齐和渐进披露降低认知负担；专业表格仍保留批量筛选、排序和比较能力。
4. **事实与判断分层。** 原始事实、平台评分、AI生成内容和用户输入使用稳定标签和版式区分，不仅依赖文案语气。
5. **风险克制醒目。** 红色只用于高风险、极高风险、阻断和不可逆错误；普通品牌强调、选中和链接使用蓝色，成功和已核实使用绿色。
6. **状态可解释。** 不以单一分数、颜色或图形作结论；任何评级均可查看含义、范围、时间和方法说明。

整体采用白色和浅灰背景、深海军蓝导航、科技蓝主操作、翡翠绿新能源辅助色，琥珀色用于中等级提醒，红色和深莓红分别用于高和极高风险。阴影只用于浮层和必要的层级分离，常规卡片优先使用边框及背景差异。禁止在正式数据页面使用大面积渐变、玻璃拟态、霓虹光、自动播放背景视频和装饰性世界地图。

普通文本与背景对比度不低于4.5:1；大号文字及非文本UI边界不低于3:1。品牌色不满足对比度时只能作装饰或背景，不可承载关键小字。禁用状态仍需可读，不能通过把文字降低到不可辨识来表达禁用。

### 20.3 字体与字号

中文界面使用系统字体栈，优先`PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`、`Source Han Sans SC`和通用`sans-serif`；拉丁字符和数字可优先使用`Inter`或系统无衬线字体。字体加载失败不得造成内容不可见或布局大幅跳动，核心功能不依赖外部字体服务。

| 样式令牌 | 字号/行高 | 建议字重 | 典型用途 |
|---|---:|---:|---|
| `type-display` | 32/42px | 600 | 首页核心标题、报告封面标题 |
| `type-h1` | 28/38px | 600 | 页面标题 |
| `type-h2` | 22/32px | 600 | 主要模块标题 |
| `type-h3` | 18/28px | 600 | 卡片组、详情分区标题 |
| `type-body-lg` | 16/26px | 400 | 重要说明、AI摘要 |
| `type-body` | 14/22px | 400 | 默认正文、表单和表格 |
| `type-body-sm` | 13/20px | 400 | 表格次要信息、来源元数据 |
| `type-caption` | 12/18px | 400 | 标签、时间和辅助注释 |
| `type-metric` | 24—32/1.2 | 600 | KPI与关键数值 |

正文不小于14px；确需显示来源元数据时可用12—13px，但必须满足对比度和行高。按钮、输入框和表格主内容不使用低于13px的字号。标题层级按文档结构使用，不为获得视觉大小跳过HTML标题级别；视觉样式与语义标签可通过组件属性分开控制。

数字列使用等宽数字特性`tabular-nums`并右对齐，单位紧邻列标题或数值，负号、小数位和千位格式由字段定义统一控制。货币同时显示币种代码或符号及基准日；日期采用明确格式，不能只写“03/04/26”。英文缩写首次出现提供中文含义或提示。

长篇政策解读、AI回答和报告预览限制正文阅读宽度，避免横跨整个大屏；中文连续正文建议每行约35—45个汉字的视觉宽度。表格、代码、网址和原文标题允许按业务规则换行或横向滚动，不通过无限缩小字号解决溢出。

### 20.4 间距与栅格

基础间距单位为4px，常用间距使用4、8、12、16、20、24、32、40、48和64px。页面和组件只引用间距令牌，不使用无规则的13px、19px等局部值。相关元素距离小于不相关分组距离，以留白建立信息层级。

PC Web应用外壳建议使用64px顶栏；第18.2节的全站一级业务导航位于顶栏。240px展开侧栏和72px收起侧栏只用于“我的工作台”、运营后台及CRM等具有稳定二级菜单的工作区，公开业务列表/详情不重复放置另一套一级侧栏。主内容在1200px及以上使用12列栅格，列间距24px；页面左右边距在宽屏为32px、普通桌面为24px。数据密集页面可使用完整可用宽度，政策正文、AI回答和设置表单应限制阅读宽度并居中或采用8+4分栏。

| 场景 | 间距/尺寸建议 | 规则 |
|---|---|---|
| 页面标题区 | 下间距24—32px | 标题、说明、更新时间和主操作形成一个整体 |
| 一级模块 | 模块间32—40px | 不用多条粗分割线代替留白 |
| 卡片内边距 | 20px，复杂详情可24px | 移动端可降为16px |
| 表单字段 | 字段组间20—24px，标签与控件8px | 相关复选项内部可用8—12px |
| 表格行高 | 默认48px，含双行信息可56—64px | V1.0不提供任意密度切换，避免页面标准不一 |
| 按钮高度 | 默认40px，小型32px，移动端主要操作44px以上 | 同一操作区按钮高度一致 |
| 圆角 | 卡片8px，输入/按钮6—8px，弹层10—12px | 不使用过度胶囊化表达所有元素 |

详情页优先采用“主内容8列＋辅助信息4列”或上下分区，来源、更新时间、风险和操作区不得被挤到不可发现的页面底部。筛选面板在宽屏可固定为左侧或顶部组合，收起后保留已生效筛选标签；页面滚动时只对确有持续操作价值的标题栏、表头或对比国家头部使用粘性定位。

弹层宽度按内容分为约480px确认、640px表单和800px复杂预览；超过一屏的复杂任务优先使用抽屉或独立页面，不在小弹窗中堆叠多步流程。弹层不能套弹层；确需二次确认时关闭或替换当前层，并保留焦点和上下文。

### 20.5 卡片和表格规范

卡片用于组合一个明确主题的信息，不把每个数字都包成独立卡片。标准卡片包含标题、可选说明、主体内容、来源/更新时间和操作区。卡片默认使用白底、1px边框和8px圆角，常态不使用重阴影；可点击卡片在悬停和键盘聚焦时显示边框/背景变化，并具有明确可访问名称。

国家和项目卡片中的评级、核实状态、覆盖等级和时间元数据位置保持稳定。受限卡片显示获准摘要、受限原因和一个明确行动，不用模糊遮罩模拟真实敏感值。AI卡片必须标注“AI生成”、生成时间、引用数量和复核状态；平台审核结论不能因放在AI卡片中失去来源性质。

表格用于精确比较和批量处理，最低包含表名或用途说明、列标题、数据体、加载/空/错误状态和分页。主要规则如下：

- 列标题使用业务术语并提供单位或定义提示；不使用只有内部人员理解的字段缩写。
- 文本左对齐，数值右对齐，短状态居中或左对齐但全站一致；同列小数位和单位一致。
- 可排序列显示未排序、升序和降序三种状态，支持键盘操作并通过可访问文本说明排序结果。
- 表头在长表中粘性固定；固定首列或操作列时保留明显分隔，不固定过多列压缩内容。
- 标题、项目名称等可换为两行并提供完整内容提示；日期、状态和关键数值不随意截断。
- 服务端分页默认每页20条，并可按统一产品配置切换；筛选、排序和分页均由URL或可恢复页面状态表达。
- 批量选择跨页时明确是“当前页”还是“全部筛选结果”，提交前显示影响数量，失败后返回逐条结果。
- 行操作不全部隐藏在悬停中；至少保留主要动作或明确的“更多操作”按钮，键盘和触屏均可发现。

国家对比表使用国家为列、指标为行，顶部国家栏和左侧指标栏按可用空间粘性固定。缺失、受限、过期、冲突和不可比使用第19章统一文案；条件格式只作辅助，不替代数值和状态。移动端不能机械压缩完整表，按20.9节使用分组指标、横向滚动或每屏两国比较。

表格加载保留表头与列宽，空状态占据数据体而非整页；局部操作失败只影响对应行。任何列表和表格都不得在前端预先取得用户无权查看的完整字段后再用CSS隐藏。

### 20.6 地图、图表和评级展示

全球地图是国家导航和区域理解工具，不作为唯一的数据访问方式。地图与国家列表共享查询结果、选中状态和图例；每次只显示机会、风险或覆盖等级中的一个主题图层。未覆盖国家使用中性灰并标明“暂未纳入覆盖”，不得套用最低或最高等级颜色。

地图应支持鼠标悬停、点击、键盘等效选择和缩放控制；悬停信息也可通过聚焦或列表获得。选中国家后在相邻面板展示名称、等级文字、更新时间和详情入口。地图边界与国家名称以统一地理数据源为准；涉及争议地区时使用产品批准的中性展示和免责声明，不由前端自行修改政治边界。

图表遵循以下规则：

1. 优先选择能直接回答问题的柱状图、折线图、点图或矩阵，不使用3D图、仪表盘堆叠和装饰性面积。
2. 标题说明指标、对象和时间范围；坐标轴显示名称、单位和基准，截断坐标轴时必须明确标识。
3. 预测、目标和历史实际使用文字/线型及图例共同区分；缺失区间断开，不用0补线。
4. Tooltip显示原值、单位、期间、来源或数据状态，并可通过键盘触发；关键信息不只存在于Tooltip。
5. 多系列颜色采用设计令牌并控制数量，超出可辨识范围时改用筛选、小多图或直接标注。
6. 每张图提供来源、数据截止时间和必要的方法说明；导出图像或报告时一并保留这些信息。
7. 对屏幕阅读器和无法使用地图/图表的用户提供同数据表格或文字摘要。

评级组件由“等级/分值＋名称＋适用范围＋更新时间＋方法入口”组成。机会评分、政策友好度、风险评分和伙伴推荐分别使用自己的规则版本，不以同一圆环暗示可直接比较。风险始终显示低、中、高、极高文字；分数为内部或无权字段时不通过图形长度泄露近似值。

趋势只有在相同定义和规则版本下存在连续数据时显示上升、稳定或下降。AI推断的趋势必须标注为情景或推断，不能使用与已审核趋势完全相同的视觉。来源冲突、统计期不同和样本不足应在图表附近显示，不只藏在“更多”弹层中。

### 20.7 标签与风险状态

所有标签由统一枚举映射组件生成，输入为稳定代码，输出为本地化文案、语义色、图标、说明和排序。前端页面不得手写“已核实”“确认项目”等近似文案。标签只承担短状态，超过一行的判断使用提示条或说明卡片。

| 业务维度 | 状态与建议样式 | 说明 |
|---|---|---|
| 国家机会等级 | 高、中、低、待评估；完整文字配国家机会蓝色序列 | 不使用项目A/B/C/D/N，也不复用风险图标或绿黄红 |
| 项目机会等级 | A优先、B关注、C观察、D谨慎、N数据不足；字母徽标配项目机会蓝色序列 | 与项目核实状态和风险等级分开 |
| 政策友好度 | 高、中、低、待评估；完整文字配独立紫色序列 | 与九类政策法律有效状态和风险等级分别展示 |
| 国家/项目风险 | 低、中、高、极高；使用绿、琥珀、红、深莓红并配不同图标 | 必须显示文字；“未评估”使用中性灰，不归入低风险 |
| 招标官方状态 | 预告、已公告、报名/投标开放、澄清、评审、已授标、取消、已关闭、未知 | 与机会窗口分字段展示；截止日到达不得自动改写为授标、取消或已关闭 |
| 伙伴推荐等级 | R1高度匹配、R2较匹配、R3可评估、R4谨慎、N信息不足 | 仅针对指定企业、国家和任务生成；不写入伙伴永久主数据，也不表示平台信用担保 |
| 项目核实 | 待核实（灰色问号）、部分核实（蓝色半实心）、已核实（绿色勾）、存在争议（高对比冲突图标） | 与机会等级、风险等级及“疑似虚假”标记分开 |
| 独立风险标记 | “高风险疑似虚假”等使用强提示条或醒目标签 | 展示依据、来源和复核状态，不创建第五种核实状态 |
| 数据覆盖 | Basic、Standard、Complete | 表示公开一致的内容深度及相应质量验收要求，不代表机会等级或会员权限；徽标不随用户权限变化 |
| 数据时效 | 当前、临近复核、逾期、来源失效、未知 | 同时显示具体时间或统计期 |
| 政策法律有效状态 | 草案、待生效、现行有效、部分有效、已修订、暂停执行、已失效、已废止、无法确认 | 完整映射第10章九类状态；与采编发布状态分开，不能仅用绿色/灰色判断是否适用 |
| AI内容身份/答案结果 | AI生成；完整回答、带警示完成、需要澄清、证据不足、权限不足、失败 | 答案结果严格映射附件H六态；“自动校验中”等仅作为任务阶段提示，不另造持久业务枚举，也不得替代人工复核状态 |
| 人工复核状态 | 待分配、审核中、待补充、通过、有条件通过、退回、关闭 | 完整映射第13章七类状态，显示复核时间与授权专业领域；人工复核不等于法律意见 |
| 权限 | 公开、注册可见、企业可见、会员可见、审批可见、仅内部 | 用户端只显示必要说明，`internal`内容不暴露 |

同一位置最多展示3个高优先级标签，其余进入“更多状态”并保持可访问；风险和阻断状态不能被折叠。标签不使用全大写长英文，不在小尺寸中塞入复杂句子。可点击标签具有明确按钮或链接语义，纯状态标签不伪装成可点击控件。

状态文案变化须与数据字典和测试同步。停用枚举在历史页面仍显示原文案及“已停用”，但不能用于新建。任何映射缺失时前端显示安全的“未知状态”并记录监控事件，不能直接把内部代码展示给用户。

### 20.8 通用组件

V1.0建立共享组件库和业务复合组件层。基础组件解决一致的交互与无障碍，业务组件封装来源、权限、风险和枚举规则。新增页面优先组合现有组件；确需新增时先定义用途、状态和API，再进入页面实现。

| 组件组 | 必备组件 | 关键状态/要求 |
|---|---|---|
| 应用框架 | 顶栏、侧栏、面包屑、页面标题、企业上下文切换 | 当前菜单、折叠、无权限、会话到期和小屏导航 |
| 操作 | 主/次/文字/危险按钮、按钮组、下拉操作 | 默认、悬停、聚焦、按下、加载、禁用；图标按钮有可访问名称 |
| 表单 | 输入框、文本域、选择器、多选、单选、复选、日期、数字、上传 | 默认、已填、聚焦、错误、成功、只读、禁用、加载和帮助说明 |
| 查询 | 全局搜索、筛选面板、筛选标签、排序、分页、保存视图 | URL同步、清除、无结果、停用条件和权限变化 |
| 数据展示 | 卡片、表格、描述列表、时间线、统计值、图表、地图 | 加载、缺失、受限、过期、冲突和部分失败 |
| 导航反馈 | 标签页、锚点目录、步骤条、进度、骨架屏、空状态、提示条、Toast | 焦点管理、历史返回、可取消任务和持久结果 |
| 浮层 | Tooltip、Popover、下拉菜单、抽屉、对话框 | 键盘关闭、焦点圈定、返回触发点；不嵌套多层弹窗 |
| 业务可信度 | 来源引用、更新时间、覆盖等级、核实状态、风险提示、方法说明 | 统一枚举、来源定位、过期/冲突和复核状态 |
| AI与报告 | 对话输入、上下文标签、回答块、引用抽屉、任务进度、报告预览 | 流式中/已校验、取消、重连、部分完成、高风险复核 |
| 权限商业化 | 权限占位、额度提示、会员权益、申请入口 | 不泄露受限值；说明原因、剩余额度、恢复时间和下一步 |

每个组件必须有稳定属性、键盘行为、可访问名称、事件、错误策略和埋点边界。基础交互状态至少包括默认、悬停、聚焦、按下、选中、加载、禁用、只读、错误和成功；业务组件另覆盖缺失、权限受限、逾期、来源冲突和待复核。

来源引用组件支持结构化事实、网页、PDF/上传文件和多来源综合结论，显示来源编号、标题、机构、日期、定位和访问状态。更新时间组件区分来源发布时间、采集时间、审核时间、最后复核时间和报告生成时间，不用一个模糊“更新时间”替代全部概念。

AI回答块在结构上固定包含生成身份、回答正文、行内引用、数据时间、局限/风险、复核状态和反馈。权限占位组件只接收服务端给出的公开说明及可执行动作，不能接收完整敏感值后自行遮盖。组件库文档应提供正常、边界、长文案、中文/英文、空值、权限和错误示例，并纳入视觉回归与无障碍测试。

### 20.9 响应式适配

响应式采用移动优先的CSS实现，但产品优先级仍以PC Web为主。统一断点建议为：0—767px移动端、768—1199px平板/窄屏、1200—1599px桌面、1600px及以上宽屏。页面不得只按设备型号判断；组件根据容器宽度决定布局时优先使用容器查询或等效方案。

| 能力 | PC Web | H5 | 小程序P1预留 |
|---|---|---|---|
| 国家导航 | 地图＋完整列表＋多维筛选 | 列表优先、简化地图或静态入口、核心筛选 | 轻量列表与收藏入口 |
| 国家对比 | 2—4国完整矩阵、AI解释和P1报告能力 | 不建设独立H5对比页；通过安全深链保留国家代码并引导PC完成 | P1候选，须另立页面编号后方可开发 |
| 项目/政策 | 完整筛选、详情、获准附件和申请 | 仅已登记H5-OPP-001项目摘要与通用表单；政策通过PC安全深链，新增H5政策页须另立P1页面编号 | 当前无项目/政策小程序页；P1候选须另立页面编号后开发 |
| AI问答 | P0提供结构化/RAG上下文、来源抽屉和报告联动；企业私有招标文件上下文仅在P1解析启用后可选 | 不建设H5 AI问答页；仅提供登录/安全深链并引导PC | P1候选，须另立页面编号并评审隐私、流式与引用交互 |
| 报告 | 配置、生成、预览、版本和下载 | 仅使用已定义的报告领取页和PC继续操作引导；不提供任务列表、生成或预览 | P1仅覆盖已登记的领取/申请页面，新增能力须另立页面编号 |
| 运营后台/CRM | 完整能力 | 仅必要通知或安全跳转，不做完整P0工作台 | 不纳入P1默认范围 |

桌面侧栏在窄屏收起为图标栏或抽屉；移动端使用顶部栏和抽屉导航。筛选器在移动端进入底部面板或全屏页，顶部持续显示已选数量和“重置/应用”；用户取消时不改变已生效条件。主要操作在移动端可固定底部，但不得遮挡表单错误、浏览器安全区或系统键盘。

表格响应式需要产品为每列定义优先级。窄屏保留对象名称、关键状态、时间和主操作，其他字段进入可展开详情；禁止仅用CSS隐藏关键风险和来源。国家对比“每屏优先显示两个国家并固定指标名称”专指PC Web在窄屏/移动浏览器下的响应式形态，不代表已建设独立H5对比页；用户切换列组时保留当前指标位置。

移动端触控目标至少44×44 CSS像素，控件间保留足够距离；不存在只能悬停才能发现的功能。输入框字体避免因浏览器自动缩放影响填写，软键盘弹出后当前字段、错误和提交操作仍可见。横竖屏切换不得丢失草稿、筛选、对比国家或AI任务连接。

同一对象使用同一稳定URL或深链策略。H5登录或跳转PC时保留来源渠道、对象ID和公开页面位置，但不传递敏感查询条件；小程序P1使用相同业务API和枚举，平台特有授权只作为身份入口，不改变会员和数据权限。

### 20.10 无障碍和可读性

V1.0以前端符合WCAG 2.2 AA级全部适用成功准则为设计和验收基线，并结合中文企业应用场景进行键盘、屏幕阅读器、缩放、色觉和触屏验证；不以“核心要求”等不可枚举口径缩小范围。对确有技术不适用的准则，测试报告须逐条说明理由、替代机制和审批人。无障碍不是上线前补丁，组件设计、语义结构和测试必须同步完成。

具体要求如下：

- 所有功能可通过键盘完成，焦点顺序与视觉顺序一致；提供“跳到主要内容”，粘性导航和弹层不吞掉焦点。
- 焦点轮廓清晰且不被CSS移除。对话框打开后焦点进入标题或首个合理控件，关闭后返回触发元素。
- 页面使用唯一主标题和连续标题层级；导航、主内容、搜索、表单和补充信息使用正确语义区域。
- 图标按钮、地图控件、标签关闭、分页和排序具有可访问名称；装饰图标从辅助技术中隐藏。
- 表单标签、帮助、必填和错误通过程序关系关联。提交失败后先通知错误摘要，再允许逐项跳转到字段。
- 风险、核实、趋势、成功和错误均使用文字/图标与颜色组合；图表提供数据表或结构化文字摘要。
- 正文与背景对比度不低于4.5:1，大文本及必要UI边界不低于3:1；高对比模式下关键控件边界仍可见。
- 页面在200%文本缩放下不丢失内容或功能；在320 CSS像素等效宽度下，除数据表、地图和确有二维关系的内容外不应同时出现双向滚动。
- 动效尊重`prefers-reduced-motion`或等效设置。非必要动效可关闭，不使用闪烁；加载和进度不依赖连续运动表达。
- 自动更新、会话超时和临时授权到期提前通知并允许合规延长；重要内容不因短时Toast消失而无法再次获取。
- 页面根节点和局部外语内容设置正确语言属性；中英文混排、数字、单位和缩写能被辅助技术合理朗读。

自动化扫描用于发现语义、名称、对比度和ARIA问题，但不能代替人工测试。P0人工测试矩阵至少覆盖Windows 11＋Edge＋NVDA、macOS＋Safari＋VoiceOver、iOS＋Safari＋VoiceOver、Android＋Chrome＋TalkBack；第38章测试基线须冻结操作系统、浏览器和读屏软件的具体版本及复测日期。每个P0核心流程均完成仅键盘操作、200%文本缩放、相应读屏组合和移动触屏测试；阻断级无障碍缺陷必须在发布前清零，其他缺陷进入有负责人和期限的台账。

### 20.11 中英文扩展预留

V1.0界面以简体中文为主，P0只交付国际化键、稳定业务代码、原文/译名字段、区域格式化能力以及中英文长文案布局测试；完整英文语言包、可见语言切换器和独立海外多语言站属于后续版本，不作为V1.0验收项。所有界面文案仍使用国际化键，不把中文写死在组件逻辑、图片、SVG路径或接口错误中；后端返回稳定代码、参数和业务数据，前端按当前简体中文语言包形成可读文案。

国际化资源按“通用组件、业务模块、状态枚举、校验错误、报告模板”分域管理。每个键具有默认中文、英文占位或正式翻译、参数说明和使用上下文，禁止依赖词序拼接完整句子。含国家、数量、日期和单位的文案使用参数化模板及复数/格式化规则。

| 内容类型 | 扩展要求 |
|---|---|
| 国家、机构和企业名称 | 保存官方原文、中文译名、英文名及别名；页面按语言显示并允许查看原名 |
| 日期与时间 | 存储统一时间，展示使用用户区域和业务时区；明确日期顺序与时区 |
| 数字、币种和单位 | 使用区域格式化；币种保留ISO代码，换算显示基准日和原值 |
| 政策与文件 | 原文和译文并存，机器翻译标识“待复核”；不能把译文称为官方文本 |
| 枚举与标签 | 代码唯一，中英文来自同一字典版本；停用状态历史可追溯 |
| 搜索 | 支持中文、英文、原文名称、ISO代码和受控别名；结果按同一实体去重 |
| AI与报告 | 记录问题语言、回答语言和引用原文语言；翻译不改变事实、单位和来源 |

设计稿为英文文本预留约30%—50%的水平增长空间，按钮和标签避免固定窄宽；长国家名、机构名和政策标题使用合理换行或省略并可查看全文。表格列宽和弹层不因英文变长而遮挡主操作。中文不使用人为插入空格实现对齐，英文不强制逐词断行。

V1.0不要求完整海外多语言站和RTL语言，但布局使用逻辑方向属性，避免大量`left/right`硬编码，为后续RTL评估降低成本。后续启用语言切换器时必须保持当前路由、对象、筛选和权限，不重新创建业务记录；缺少翻译时按配置回退到简体中文并显式记录监控，不显示国际化键。

### 20.12 设计稿交付规范

设计交付不是一组静态页面截图，而是“设计令牌＋组件库＋核心流程＋响应式状态＋交互说明＋验收依据”的完整包。设计文件应具有清晰页面、版本和责任人，产品、设计、前端和测试使用同一需求编号及枚举字典。

正式交付至少包含：

| 交付项 | 内容要求 | 验收用途 |
|---|---|---|
| 设计基础 | 品牌色、语义色、字体、字号、间距、栅格、圆角、阴影、图标和动效令牌 | 前端令牌实现与视觉回归基线 |
| 组件库 | 基础组件及业务组件的尺寸、属性、全部状态、长文案和无障碍说明 | 组件开发、Story/示例和单元测试 |
| 页面设计 | P0 PC主页面、后台/CRM工作台及其规定响应式状态；H5、小程序仅交付已列入P1页面清单的规划稿 | 页面实现、P0/P1边界和权限矩阵核对；P1规划稿不阻断V1.0上线 |
| 核心流程 | 第19章各流程的主路径、异常、空、权限、复核和恢复路径 | 产品评审、端到端测试 |
| 响应式稿 | 至少桌面、窄屏和移动关键断点，注明重排/隐藏/替换规则 | CSS实现和设备测试 |
| 交互原型 | 导航、筛选、对比、弹层、表单、AI流式、报告任务和状态转换 | 操作行为和焦点顺序验收 |
| 文案与枚举 | 页面文案、错误、空状态、状态映射、中英文键及免责声明 | 避免开发临时造词，支持自动化断言 |
| 图表与地图规范 | 数据映射、色阶、图例、Tooltip、缺失值、来源和可访问替代 | 可视化开发与数据质量测试 |
| 资源清单 | 图标、插图、地图资源和导出规格；注明许可与压缩要求 | 构建、性能与版权合规 |
| 变更记录 | 设计版本、需求编号、变更原因、影响页面、确认人和日期 | 防止静默改稿和实现错版 |

第三篇一经确认，20.4的64/240/72px应用外壳、栅格与间距，20.5的默认每页20条，20.9的响应式断点，以及20.11的英文文案增长30%—50%测试空间均作为V1.0默认设计令牌和验收基线冻结。后续调整必须更新令牌、受影响页面和测试基线，并按第1.9节需求变更机制留痕，不再作为开发人员可自行选择的开放建议值。

组件使用变体、属性和自动布局表达，不为每个页面复制脱离组件库的独立图层。图层、组件和页面采用稳定命名；颜色、间距和字体引用令牌。图标以SVG或适合终端的矢量形式交付，位图明确1x/2x尺寸、压缩和替代文本；业务文字不得烘焙进不可翻译图片。

每个页面标注路由、适用角色、会员/权限条件、数据来源、关键字段、主操作、事件、加载/空/错误状态和埋点。交互说明重点写“触发条件—系统动作—页面反馈—失败恢复”，不重复描述截图上显而易见的像素。复杂表单提供字段Schema或引用数据字典，复杂表格提供列优先级、排序、固定、分页和移动端策略。

交付流程为“产品流程确认—设计系统/页面设计—设计评审—开发走查—视觉与交互验收—变更归档”。进入开发前，P0页面必须具备主流程、业务枚举、权限、响应式和异常状态；只有理想状态截图的页面不满足开发就绪条件。开发过程中发现数据或权限逻辑变化时，先更新需求和组件说明，再修改页面，不由前端自行推断设计。

设计验收采用页面和组件双层检查。组件层核对令牌、状态、键盘、长文案和无障碍；页面层核对信息层级、数据真实性、权限、来源、响应式和业务流程。视觉差异按关键程度分级：影响风险、权限、数据含义和操作结果的差异为阻断；一般间距或非关键装饰差异按统一容差整改，不以截图像素完全一致代替可用性验收。
