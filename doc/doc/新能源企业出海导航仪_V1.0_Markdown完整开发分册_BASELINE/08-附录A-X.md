## 附录A 需求编号与功能优先级基线

附录A控制“为什么做、做什么、何时做、如何验收”。每项需求必须使用唯一`FR-*`或`NFR-*`编号，并至少具备模块、用户价值、优先级、版本、依赖、验收标准、责任人和状态。历史同号异义、拆分合并和字段迁移必须进入《编号纠错映射》，不得静默覆盖。

### 最小控制字段

| 字段 | 要求 |
|---|---|
| 规范编号 | 全局唯一；上线后不复用 |
| 需求摘要 | 一个可验证结果，不写部门活动 |
| 优先级 | P0—P3；P0为V1.0上线必需 |
| 版本范围 | D0—D4、V0.1、V0.5、V1.0或后续版本 |
| 依赖 | 数据、页面、API、权限、AI、合规和第三方依赖 |
| 验收标准 | 可被独立测试，不使用“正常”“友好”等模糊词 |
| 变更依据 | 变更单、批准人、日期和影响评估 |

**验收门：** P0需求无重复编号、无空验收标准、无未解决P0依赖；每项P0需求至少映射一个页面或接口、一个权限控制和一个测试用例。附录A通过后才能冻结迭代范围。

## 附录B 用户角色、企业隔离与权限矩阵

附录B定义角色、会员权益、企业上下文、对象范围、字段范围和操作权限的叠加规则。页面隐藏不等于授权，所有受控操作必须在服务端执行身份、企业、角色、权益、字段和对象状态校验。

### 权限判定顺序

1. 验证账号状态和会话；
2. 确定当前企业上下文；
3. 校验角色和最小权限；
4. 校验会员权益、额度与有效期；
5. 校验对象归属、发布状态和字段敏感级别；
6. 执行频率、下载、披露和二次审批限制；
7. 记录允许或拒绝的审计事件。

**验收门：** 权限矩阵覆盖游客、注册用户、企业成员、企业管理员、企业会员、数据编辑、数据审核、运营、商务和系统管理员；跨企业、越权字段、过期权益、撤权缓存和批量导出均有负向用例。任何P0越权用例失败均阻断发布。

## 附录C 页面、路由、埋点与原型追踪

附录C是页面开发准入台账。每个页面以`PAGE-*`编号管理端类型、路由、目标用户、主要任务、需求、API、权限、状态、埋点、原型和测试映射。相同业务对象的Web、H5和后台页面可以共享能力，但不得共享不适用的路由与权限。

### 页面开发准入条件

| 检查项 | P0要求 |
|---|---|
| 业务目的 | 一个主要任务和明确完成信号 |
| 数据状态 | 真实种子数据或正式契约样本可用 |
| 交互状态 | 加载、空、错误、无权、过期、部分成功、离线/重试 |
| API与权限 | 至少一个已评审契约；敏感字段有权限说明 |
| 原型 | 关键视口和主要流程已评审 |
| 测试 | 功能、权限、响应式和可访问性用例可执行 |
| 埋点 | 事件代码、触发时机、同意状态和字段白名单明确 |

未满足准入条件的页面保持“候选”或“待补齐”，不得因已有视觉稿直接进入完成状态。

## 附录D 用户流程、状态机与异常处理

附录D将用户旅程与业务状态机统一。所有状态迁移必须明确来源状态、目标状态、触发者、前置条件、校验、审计、通知、回退和幂等策略。申请审批、数据发布、报告生成、采集运行、质量问题、评分模型和知识库发布采用独立状态机，不得共用含义不明的`status`。

**必备异常：** 重复提交、并发修改、过期版本、依赖超时、部分成功、人工驳回、撤权、对象下架、来源失效、文件恶意、模型拒答和消息重复。

**验收门：** 正向和负向迁移均有测试；非法迁移返回稳定错误码；高风险操作具备二次确认或职责分离；重试不会产生重复有效记录；历史状态和操作人可审计。

## 附录E 数据实体关系与主外键

附录E定义国家、政策、风险、项目、招标、伙伴、企业、用户、来源、快照、发布版本、评分、报告、知识片段、申请、线索和审计等权威实体及关系。搜索索引、向量索引、缓存和报表快照均为派生存储，不得反向成为事实主库。

### 关系设计硬约束

- 业务主键与数据库主键分离，外部来源ID通过映射表管理；
- 发布记录、来源快照、评分结果和报告均采用不可变版本；
- 软删除、下架和撤权保留墓碑及历史引用；
- 企业个性化评价按企业画像版本隔离，不覆盖平台通用评价；
- 所有关键事实可追溯到字段来源、原始快照、采集运行和审核记录；
- 跨实体删除必须明确限制、级联、置空或归档策略。

**验收门：** 无孤立外键；多对多关系有显式关联实体；生命周期、唯一约束和索引目的明确；迁移脚本可回滚并能重放历史快照。

## 附录F 核心数据字典与字段控制

附录F是数据库、API、导入、质量、权限、搜索和AI之间的字段契约。字段必须登记实体、代码、中文名、英文名、类型、单位、是否必填、敏感级别、来源策略、值状态、更新频率、质量规则和说明。

### 字段值语义

`null`只表示没有有效数值；缺失原因由`value_status`区分未采集、待核实、未公开、不适用、来源冲突或失效。数值0必须有来源证据，不能用0替代缺失。日期须区分事实日期、发布日期、采集时间、审核时间和生效区间。

**验收门：** D0冻结的核心字段均有唯一代码和类型；多语言、货币、单位、时区和精度明确；敏感字段具备脱敏和导出规则；字段变化有向前/向后兼容、迁移和回滚方案。

## 附录G 状态、标签与枚举字典

附录G统一代码值、显示文案、适用对象、迁移规则和终态语义。代码值采用稳定英文小写或既有规范代码，中文只作为显示文本；上线后不得直接改名或复用。

### 枚举治理规则

- 发布状态、质量状态、时效状态、核实状态、风险等级和权限状态相互独立；
- 低/中/高/极高风险与A—D机会等级不得混用；
- 未知、缺失、待核实、存在争议和不适用必须区分；
- 废弃枚举先标记、兼容读取、迁移存量，再停止新写入；
- 前端、后端、数据库、AI Schema和测试从同一枚举源生成或校验。

**验收门：** 无同码异义、同义多码和未登记生产代码；每个状态机明确初始、终态和可达路径；历史迁移记录完整。

## 附录H 数据源目录与合法使用登记

附录H控制来源准入、权威等级、许可边界和健康状态。公开可访问不等于允许批量抓取、长期存储、再分发或用于AI索引；来源在使用前必须记录机构、入口、内容类型、国家、权威级别、访问方式、条款/许可快照、更新频率、保存边界、AI使用边界、责任人和复核日期。

### 来源等级

| 等级 | 定义 | 典型用途 |
|---|---|---|
| A | 法律法规库、政府部门、监管机构、统计局、电网/采购主体官方发布 | 关键事实和最终核验 |
| B | 世界银行、ADB、AfDB、IRENA、UN等国际组织 | 跨国标准化和补充核验 |
| C | 交易所公告、企业官网、项目主体公告、审计报告 | 企业/项目事实 |
| D | 专业媒体、行业协会、研究机构 | 线索发现和背景解释 |
| E | 聚合平台、社交媒体、匿名信息 | 仅作线索，不直接发布 |

**验收门：** 关键来源均完成合法使用复核；禁用、阻断或待复核来源不能进入自动采集；每类核心事实至少有优先来源和替代来源；条款变化能触发停采、撤权和影响评估。

## 附录I 数据采集任务、调度与批次台账

附录I把来源转化为可执行任务。每个任务登记任务编号、来源、实体、采集方式、范围、频率、时区、水位、幂等键、去重键、限速、超时、重试、模式漂移、失败处置、责任人和SLA。

### 采集运行最小记录

| 记录 | 要求 |
|---|---|
| 运行ID | 全局唯一，与任务和批次关联 |
| 输入范围 | 查询参数、时间窗、页码或文件清单 |
| 结果 | 成功、部分成功、失败、阻断或取消 |
| 数量 | 发现、下载、解析、新增、更新、重复、失败 |
| 水位 | 仅在完整提交成功后推进 |
| 证据 | 原始文件/页面快照、哈希和响应元数据 |
| 错误 | 稳定错误类别、重试次数和人工处置 |

**验收门：** 重跑幂等；失败不推进成功水位；访问拒绝、验证码或条款风险触发停止而不是绕过；模式漂移先保留原始证据、暂停错误映射并告警。

## 附录J 数据质量、审核与发布门禁

附录J管理完整性、准确性、一致性、唯一性、时效性、可追溯性和权限合规。质量规则必须有规则编号、对象、字段、严重度、触发逻辑、阻断范围、责任人、处置SLA、复验和豁免期限。

### 质量问题等级

| 等级 | 示例 | 处置 |
|---|---|---|
| P0 | 关键事实无来源、跨企业泄露、错误发布、恶意文件进入正式区 | 立即阻断、升级和回滚 |
| P1 | 关键字段冲突、严重过期、实体误合并、评分门槛失效 | 1个工作日内受理并限期修复 |
| P2 | 非关键字段缺失、翻译待复核、展示一致性问题 | 纳入批次整改 |
| P3 | 优化建议、低影响元数据缺口 | 进入改进池 |

**验收门：** 发布前P0为0；印尼核心字段完整率达到D4门槛；关键事实100%可追溯；抽样准确率和重复率达到计划阈值；编辑与审核职责分离；豁免具备批准人、理由和到期日。

## 附录K 评分、评级、推荐与模型版本

附录K管理国家机会、政策友好度、国家风险、项目机会、项目核实、伙伴匹配、数据可信度、国家覆盖和推荐优先级等模型。每个模型保存指标、方向、标准化、权重、缺失处理、置信度、硬门槛、分级阈值、解释模板、适用范围和版本。

**硬规则：**

- 缺失值不按0分处理；
- 低置信度结果必须收缩或转待评估，不输出虚假精确；
- 制裁、权限、核实争议和来源失效等硬门槛优先于加权得分；
- 通用评价与企业个性化评价按上下文和输入快照隔离；
- 商业赞助、会员或合作关系不得改变自然评分；
- 页面、API、AI和导出读取同一已发布结果ID。

**验收门：** 边界、缺失、低置信、硬门槛、人工调整、版本回放、灰度、回滚和多端一致性用例全部通过。

## 附录L API、事件、错误码与接口契约

附录L统一接口编号、方法、路径、版本、认证、权限、幂等、限流、输入、输出、错误、事件和状态。OpenAPI是同步接口权威契约；异步事件和任务结果另行登记Schema及版本。

### 接口冻结检查

- 路径、方法和资源命名一致；
- 分页、排序、筛选、时间、货币和多语言语义统一；
- 写操作声明幂等键、并发版本或冲突处理；
- 文件上传具备大小、类型、扫描、隔离和下载授权；
- 长任务返回任务ID，支持查询、取消和失败定位；
- 错误码稳定且不泄露敏感内部信息；
- 破坏性变更采用新版本或正式弃用周期。

**验收门：** 契约测试、越权测试、并发测试、重试测试和兼容测试通过；前端不依赖未登记字段；生产接口与文档版本一致。

## 附录M 设计令牌、组件与多端前端规范

附录M统一颜色、字号、间距、圆角、阴影、图标、栅格、断点、状态、组件和无障碍规则。国家情报页面保持低密度、强层级和来源可见；风险色只表达风险，不用于装饰。

### 核心前端门禁

| 类别 | 要求 |
|---|---|
| 组件 | 按钮、表单、表格、筛选、状态、来源、引用、权限提示统一 |
| 响应式 | 桌面、平板、移动端关键流程可完成 |
| 可访问性 | 键盘可达、焦点可见、对比度、语义标签和错误提示 |
| 性能 | 代码分割、图片与表格虚拟化、请求取消、缓存策略 |
| 状态 | 加载、空、错误、无权、过期、部分数据和重试 |
| 国际化 | 简体中文优先，文案和布局具备中英文扩展能力 |

**验收门：** P0页面通过设计评审、视觉回归、响应式、键盘和对比度检查；组件差异有明确例外而非复制分叉。

## 附录N AI任务路由与模型接入配置

附录N定义任务类型、风险等级、模型候选、上下文上限、结构化输出、工具权限、超时、重试、降级、成本和日志。云端与本地模型可并存，但必须通过统一适配层和配置版本接入。

**路由原则：** 结构化查询优先于生成；低风险摘要可用高性价比模型；跨来源分析和报告使用能力更强模型；法律、政策、投资和项目真实性等高风险任务必须有引用、拒答和人工复核门；模型不可直接写入正式业务事实。

**验收门：** 未配置任务不得调用模型；密钥不进入客户端或日志；超时、限额和供应商故障有降级；结构化Schema验证失败不得以自由文本冒充成功。

## 附录O RAG知识库、Prompt与工作流

附录O管理文档解析、切分、元数据、Embedding、索引、检索、重排、引用、Prompt、Skill和多步骤工作流。检索前后均执行企业、角色、字段、发布状态和撤权过滤。

### RAG证据链

`回答片段 → 引用 → chunk版本 → 文档版本 → 来源快照 → 来源登记 → 采集运行 → 审核发布记录`

**验收门：** 每个关键结论有可打开引用；来源撤权、记录下架和企业权限变化按SLA从检索结果失效；索引可由已发布数据重建；Prompt、工具和工作流均有版本、测试和回滚。

## 附录P AI评测指标、数据集与用例

附录P建立离线、灰度和在线三层评测。指标至少包括任务成功率、事实正确率、引用覆盖率、引用支持率、权限泄露率、幻觉率、拒答正确率、结构化输出通过率、延迟和单位任务成本。

### 发布硬门

- 权限泄露和高风险无来源结论为0容忍；
- 关键事实必须被引用直接支持；
- 模型升级在冻结集上不劣化核心任务；
- 评测集包含正常、缺失、冲突、过期、诱导、越权和提示注入样本；
- 人工评审记录标准、样本、评审人和分歧处理。

未达到门槛的版本只能继续测试或回滚，不得通过调整展示文案掩盖质量问题。
