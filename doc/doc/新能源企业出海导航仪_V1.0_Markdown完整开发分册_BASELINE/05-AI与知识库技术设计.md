## 第26章 AI总体技术架构

本章定义AI能力在平台中的责任边界、服务分层、任务路由、模型降级、额度与审计。AI不得绕过结构化权限、数据发布状态和来源授权；凡可由确定性查询、规则引擎或模板完成的任务，优先使用确定性组件。

### 26.1 AI使用目标

围绕国家筛选、政策解读、项目研判、伙伴匹配、报告生成和后台采编提效建立六类AI能力。每项能力必须绑定业务对象、用户任务、允许使用的数据范围、输出契约和可量化验收指标，不以“接入大模型”作为完成标准。

实现时必须形成可审计配置或运行记录，并将模型、Prompt、知识库、权限上下文、成本与trace_id纳入同一调用链。验收至少覆盖正常、超时、取消、配额不足、供应商不可用和越权六类场景。

## 第27章 RAG知识库设计

RAG是平台AI使用可核验事实的主路径。权威关系库、原始证据和发布版本仍是事实源；向量库、关键词索引和分块文本均为可重建派生物，必须继承对象权限、发布状态、来源许可、有效期和删除状态。

### 27.1 知识库范围

首期纳入已发布国家画像、政策条款、风险说明、项目与招标公开材料、伙伴能力证据、平台方法论和获准使用的内部文档。不纳入登录凭证、密钥、未经授权的企业私有材料、已下架正文和仅凭传闻形成的内容。

该环节的输入、输出、版本、哈希和状态必须可查询；任何索引派生结果均不得覆盖原始文件和发布事实。验收同时检查召回质量、权限零泄漏、历史复现和撤权失效。

### 27.2 文档解析

解析流水线执行文件安全扫描、格式识别、OCR、版面分区、表格提取、页码/标题定位、语言检测和质量评分。原文件哈希与解析器版本固定；低质量OCR、密码文件和结构异常进入人工队列，不直接发布索引。

该环节的输入、输出、版本、哈希和状态必须可查询；任何索引派生结果均不得覆盖原始文件和发布事实。验收同时检查召回质量、权限零泄漏、历史复现和撤权失效。

### 27.3 内容分块

优先按标题、条款、段落、表格和列表语义分块，目标中文400—900字并保留10%—15%受控重叠；不得跨政策条款、表格行组或权限边界拼块。每个chunk可回指页码、段落、坐标或原文锚点。

该环节的输入、输出、版本、哈希和状态必须可查询；任何索引派生结果均不得覆盖原始文件和发布事实。验收同时检查召回质量、权限零泄漏、历史复现和撤权失效。

## 第28章 Prompt、Skill与AI工作流

Prompt、Skill和工作流都是受版本控制的生产配置，不是散落在代码中的字符串。工作流负责步骤、状态、权限和重试；Skill封装可复用能力；Prompt规定模型角色、输入输出和边界，三者均需评测、审批和回滚。

## 第29章 AI安全与效果评测

AI上线采用“离线评测门禁＋灰度观测＋人工抽检＋问题回灌”的闭环。安全和质量指标按任务、国家、语言、模型、Prompt、知识库与风险等级分层，不允许以总体平均值掩盖高风险失败。

### 29.1 AI回答边界

AI可提供信息检索、比较、摘要、解释和决策支持，不替代法律、税务、投资、工程签章或政府审批。涉及实时性、受限信息和个案结论时必须说明截止时间、数据范围和复核建议。

指标必须按任务、风险、语言、国家、模型、Prompt和知识库版本分层统计。任一高风险阻断项失败即判候选版本不合格，不得用普通问题的平均提升抵消。
